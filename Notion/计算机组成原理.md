# 计算机组成原理

- 指令集: CPU硬件能理解并执行的**所有**指令的集合与标准规范
- 机器操作码: 专门用来指示CPU应该执行什么具体操作的二进制代码段
- 机器指令 = 机器操作码(执行什么操作) + 地址码(对谁进行)

- $[]$表示取该地址或寄存器中的"数据/内容"
- 没有中括号则表示"部件/寄存器本身"或"地址编号"
	- $[M]\xrightarrow{}X$表示将内存地址M中的存储的具体数值当道通用寄存器X中

- 寄存器: CPU/IO接口内部一小块用来临时存取二进制数据/指令的高速存储单元
	- 特点: 读写速度极快(与CPU同频),容量极小,紧贴逻辑运算单元和控制单元

## 计算机的基本组成

- 软件: 由具有各类特征功能的信息组成
	- 系统软件 -> 为管理整个计算机系统所编制的程序
	- 应用软件 -> 为实现用户应用所编制的各种程序
- 硬件: 计算机的实体
	- 主机
	- 外设

- **冯诺依曼计算机的特点
	- 计算机由五大部件组成
		- 运算器: 负责进行算术运算和逻辑运算
		- 控制器: 负责从存储器中读取指令,对指令进行译码,并向各部件发出控制信号以协调工作
		- 存储器: 存放数据和程序
		- 输入设备: 将信息转换成机器能识别的形式
		- 输出设备: 将结果转换成人熟悉的形式
	- 指令和数据以同等地位位于存储器,可按地址寻访
	- 指令和数据用二进制表示
	- 指令由操作码和地址码组成
	- **存储程序** -> 具有存储结构的机器称为计算机
	- 以**运算器**为核心

### 系统复杂性管理方法

- **层次化与抽象
	- 分层设计: 将负责的计算机系统自底向上划分为不同的抽象层
		- 每一层都对上层隐藏内部实现的物理细节,仅通过明确定义的接口对外提供服务

- **模块化与结构化
	- 将功能紧密相关的逻辑组合在一起,模块之间通过标准的总线或数据通路通信
	- 标准部件标准化,避免重复设计

- **规范化与标准化
	- 使用结构高度规整的硬件阵列来替代零散的组合逻辑
	- 在RISC架构设计中,尽量采用固定长度的指令格式和统一的译码规则,简化译码器电路中的设计复杂性

- **局部性原理与层次化存储
	- **时间局部性与空间局部性**: 意识到程序访问数据和指令具有极强的时间与空间集中性
	- **层次化构建**: 构建"寄存器 -> L1/L2/L3 Cache -> 主存 -> 外存"的存储金字塔
	- **透明性管理**: 通过硬件机制或操作系统自动管理数据的流动,化解速度与容量的矛盾

### 程序转换为指令

- 将人类的思想转换为计算机硬件能够识别并自动执行的二进制指令序列,并将其装入主存开始运行的过程

$$高级语言/数学算式 \xrightarrow{编制与翻译}汇编/机器指令 \xrightarrow{分配与装入} 主存布局 \xrightarrow{启动指令}设置PC\xrightarrow{自动执行}硬件回路运行 $$
- 指令 = 操作码 + 地址码
- 指令和数据都是保存在存储器中的

#### 存储器的基本组成

- 存储体:  由成千上万个存储单元按规则矩阵排列组成的整体
	- 存储单元: 存储数据的电路单元
		- 一个存储单元 = 一个字节
		- 存储单元地址: 每个存储元都有一个唯一的编号
	- 存储元: 存储体的最小物理单元
	- 存储字: 若干个存储单元组合在一起
		- CPU每次从内存里"搬运数据"或者"读取指令"时,往往是按一个存储字的大小进行拿取
			- 一个存储字包含几个字节,取绝对机器字长
				- 如果机器是32位的,一个存储字 = 4个字节
				- 如果机器是64位的,一个存储字 = 8个字节
		- 存储位长: 一个存储字包含的位数
- 译码器: 将二进制地址转换为"物理选通信号"
	- 通过地址总线得到MAR输出的二进制地址码.然后让要取的存储单元与数据总线接通
- 驱动器: 放大信号的功率
	- 译码器的输出信号功率很弱,带不动存储体里成千上万个晶体管电容.
	- 驱动器就像一个"信号放大器",把译码器输出的弱信号增强,从而有足够的电流去开闭/激活存储体中选中的存储单元
- MAR与MDR:
	- MAR(存储器地址寄存器)
		- 功能
			- 接受与锁存地址: 暂存CPU发出的主存单元物理地址
			- 驱动地址总线: 地址总线将这个地址送到主存的译码器输入端,从而激活对应的选通线
		- 作用
			- 控制物理寻址: MAR的位数能直接决定CPU硬件一次能够直接寻址的最大存储单元个数
			- 时序与电平隔离: CPU内部的运行速度极快,而外部总线和主存相对较慢.MAR能把CPU发出的地址信号锁存住,确保在整个读/写周期内,给主存译码器的地址信号始终稳定
	- MDR(存储器数据寄存器)
		- 功能
			- 数据中转与暂存: 无论是从主存读取数据/指令,还是向主存写入数据,所有二进制码都必须在MDR停靠中转
			- 隔离与双向缓冲:宽约CPU内部数据通路与外部数据总线,起到双向电平匹配与缓冲的作用
	- 读数据:$$主存存储器 \xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}CPU内部(IR或ACC/X/MQ)$$
	- 写数据:$$CPU内部(ACC等)\xrightarrow{}MDR\xrightarrow{}数据总线\xrightarrow{}主存存储器$$
	- 在逻辑功能上,MAR/MDR是主存储器的地址与数据缓冲接口
	- 在物理上,MAR/MDR是集成在CPU内部的寄存器电路

- 按地址进行寻址

#### 运算器的组成与功能

- 具备的寄存器
	- ACC(累加器):是CPU内部运算器的核心部件之一.他是一个高速暂存单元,专门用来临时存放算术逻辑运算的操作数或中间/最终结果
		- 避免了频繁访问主存,大幅提高执行效率
		- 简化指令长度
	- X(操作数寄存器):内存数据缓冲区
	- MQ(乘商寄存器):辅助/扩展寄存器

**加法操作

指令: 加(进行的操作) M(加数的地址)
初态: ACC -> 被加数
步骤:
	$[M]\xrightarrow{}X$
	在ALU中完成: $[ACC]+[X]\xrightarrow{}ACC$

**减法操作

指令: 减 M
初态: ACC -> 被减数
步骤:
     $[M]\xrightarrow{}X$
     在ALU中完成: $[ACC] - [X] \xrightarrow{} ACC$

**乘法操作

指令: 乘 M
初态: ACC 被乘数
步骤:
	$[M]\xrightarrow{}MQ$
	$[ACC]\xrightarrow{}X$
	$0\xrightarrow{}ACC$
	$[x]×[MQ]\xrightarrow{}ACC//MQ$ 
- 定点数乘法运算执行时,乘积的字长通常会扩大为原来的两倍,一个寄存器就不够用了
	- 我们可以让ACC存储高位的数据,MQ存储低位的数据

**除法操作

指令: 除 M
初态:ACC 被除数
步骤:
	$[M]\xrightarrow{}X$
	$[ACC]÷[X]\xrightarrow{}MQ$
- 余数在ACC中

#### 控制器的组成与功能

**功能
- **解释一条指令**: 控制器的译码器将从内存或指令缓存中读取到二进制机器指令进行分析破译,并将其转化为一串用于控制CPU内部各个部件协调工作的微操作控制信号的过程
- **保证指令的按序执行

**基本组成

- PC(程序计数器): 存放了当前预执行指令的地址,具有计数功能 -> 取指令 (PC) + 1 -> PC
- IR(指令寄存器): 存放当前预执行的指令
- CU(控制单元): 控制CPU内部所有开关的通断,数据流向的闸门,以及各个功能部件的操作模式

- 整个过程
	- PC将指令地址送到地址总线,内存根据这个地址把指令读出,通过数据总线送入CPU的IR.同时PC自动递增指向下一条指令
	- 指令放入IR后,CU将IR里的二进制代码翻译成一排排高低电平信号,去驱动DLU计算,驱动总线切换,驱动寄存器读写.

**完成一条指令的过程

- 取数指令:
	- 先取指令:$$PC\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器(负责数据总线与对应的存储单元对接)$$$$内存目标存储单元\xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}IR\xrightarrow{}CU$$
	- 取数:$$IR\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器$$$$存储单元\xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}ACC$$
- 存数指令:
	- 先取指令:$$PC\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器$$$$存储单元\xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}IR\xrightarrow{}CU$$
	- 存数:$$IR\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器$$$$ACC\xrightarrow{}MDR\xrightarrow{}数据总线\xrightarrow{}存储单元$$

### 计算机硬件的主要计数指标

- 机器字长: CPU一次能处理数据的位数,与CPU中的寄存器位数有关
- 运算速度:
	- 主频: CPU内部数字电路的时钟信号频率
		- 通常以GHz为单位.CPU内部的晶体管和触发器在每一个时钟周期的状态翻转,都依赖这个统一的"节拍器"
		- 主频越高不等于指令执行地越快,与CPU架构设计等有关
	- 核数,每个核支持的线程数
		- 指令最终是由CPU的硬件电路来完成的,线程只是操作系统进行调度和分配CPU时间片的基本单元
		- CPU与线程之间的关系:
			- 操作系统把一个线程调度到某个CPU个核心上运行,本质是把该线程的上下文(比如把线程下一条要执行的指令地址装入PC寄存器)加载到物理硬件中
			- 随后,CPU的硬件逻辑电路开始顺次读取PC指向的指令并加以完成
	- CPI: 执行一条指令所需时钟周期数
		- 先执行一段程序,计算里面指令出现的频率,再对各种指令根据频率加权
	- IPC: 一个时间周期内,能执行多少条指令
	- MIPS：每秒能够执行多少百万条指令
		- 存在的弊端:
			- 忽略了不同指令的复杂度
			- 无法跨不同指令集架构(ISA,Intruction Set Architecture)进行比较
				- RISC(精简指令集)架构倾向于用多条简单指令组合完成一个复杂任务
				- CISC(复杂指令集)架构可能只需一条复杂指令就能完成相同的任务
				- 可能导致完成同一个任务的总时间相同,但指令数不等
			- 忽略了程序编译器的优化影响
	- FLOPS: 每秒浮点运算次数
- 存储容量(存放二进制信息的总位数)
	- 主存储量
		- 存储单元个数 × 存储字长
		- 字节数
	- 辅存容量


## 总线(BUS)

- 总线在物理本质上就是多根信号线(以及电源线,地线)组成的公共传输通道,连接各个部件的信息传输通道

**传输种类
- 串行传输: 数据按位顺序,在一条数据通道上像"糖葫芦"一样一位接着一位按时间顺序传递
	- 虽然每次只有一根数据线能跑,但是频率极高,速度极快
- 并行传输: 数据在多条数据线上同时传输
	- 多条数据线上的数据必须齐头并行,一旦有一条数据线上的数据卡住,其他路都得等着
	- 在高频情况下,走线长度相差几微米,数据就会不同步到达,数据就会彻底混乱
	- 多条线挤在一起,高频高压下会使相邻走线上产生严重的感应噪声,信号失真

**总线的分类
- 片内总线: 芯片内部的总线
- 系统总线: 计算机各部件之间的信息传输线
	- 数据总线
		- 双向
		- **传输内容**: 实际的数据,指令,或运算结果
		- 在CPU,内存,外设之间搬运原始数据,其宽度决定了一次能传输的数据量
	- 地址总线
		- 单向 -> 谁请求,谁指定地址
		- **传输内容**: 目标内存单元或外设端口的物理地址
		- 告诉系统"数据要发给谁"或"从哪里读取数据"
		
		- 如果是**按字节寻址**
			- 地址线上的二进制数值,直接指向内存中某个具体的**字节单元**
		- 如果是**按字寻址**
			- 这种情况下内存是以**字**为单位进行编号的
	- 控制总线:
		- 双向
		- **传输内容**: 读写控制,中断请求,时钟同步,总线响应
		- 负责协调和同步各个部件的操作,确保数据传输不会冲突
- 通信总线: 用于计算机系统之间或计算机系统与其他系统之间的通信
	- 传输方式
		- 串行通信总线
		- 并行通信总线

### 总线的特性及性能指标

- **总线特性
	- 机械特性: 尺寸,形状,管脚数及排列顺序
	- 电气特性: 传输方向和有效的电平范围
	- 功能特性: 每根传输线的功能(地址,数据,控制)
	- 时间特性: 信号的时序关系

- **总线的性能指标
	- 总线的宽度: 数据线的根数
	- 标准传输率: 每秒传输的最大字节数
	- 时钟同步/异步: 同步,不同步
	- 总线复用: 地址线与数据线复用
	- 信号线数: 地址线,数据线和控制线的总和
	- 总线控制方式: 突发,自动,仲裁,逻辑,计数
	- 其他指标: 负载能力(能挂多少IO设备)

### 总线的控制

- **总线的判优控制
	- 主设备 -> 对总线有控制权
	- 从设备 -> 响应从主设备发来的总线命令
	
	- 有些设备既可以作为主设备,也可以作为从设备
	- 有些总线上可以有多个主设备,但有些总线上只能有一个主设备

	- **方式
		- **集中式
			- **链式查询
				- ![[Pasted image 20260926103144.png]]
				- **结构**
					- 数据线
					- 地址线
					- BR(Bus Request,总线请求)
						- 所有设备共享一条BR线.只要有任意一个或多个设备想用总线,就会向BR拉有效信号
					- BG(Bus Grant,总线响应/允许)
						- 总线控制器收到BR后,发出BG信号.BG信号从距离控制器最近的设备,物理上一级一级串联传下去
							- 如果设备i发起的请求,设备i收到输入端$BG_{in}$后,不再往下传$BG_{out}$,同时将BS拉高,正式接管总线
							- 如果设备i没有请求,就会将$BG_{in}$原封不动地传给下一级$BG_{out}$
					- BS(Bus Busy,总线忙)
				- **逻辑**: 各个 I/O 设备通过 BR 进行总线请求，然后 BG 通过类似于链式的方式对各个接口进行访问，看哪个需要占用总线，如果发现有需要占用总线的接口，这个接口就被同意占用总线，然后就在 BS 中发送总线忙，接着就可以调用数据线和地址线了。
				- **优点**
					- 结构简单,硬件成本低: 无论多少个I/O设备,总线控制器只需要3条控制线,极大地节省了电路布线和接口引脚
					- 扩充设备方便: 只需要在链末串联新设备即可
					- 天然实现优先级判优: 物理位置决定优先级
				- **缺点**
					- 对电路故障极度敏感: BG信号是串联通过每个接口的,如果中间某个接口出现硬件损坏或线路断路,该接口之后的所有设备都将瘫痪
					- 存在"饥饿现象": 如果高优先级的设备频繁请求总线,位于链条末尾的高序列设备可能长期无法获得总线控制权
					- 查询速度慢: 链条越长,挂载设备越多,信号传导末端所需的时间就越长,限制了总线的工作频率
			- **计数器定时查询
				- 是一种通过软件/逻辑可调的设备地址来决定总线使用权的集中式仲裁方式
				- ![[Pasted image 20260926110218.png]]
				- **构成
					- 数据线
					- 地址线
					- 若干个设备地址线($\log_2 N$条设备地址线(使用二进制进行表示地址))
					- BR(总线请求)
					- BS(总线忙)
				- **过程**
					- 发起请求: 一个或多个I/O设备通过公用的BR线向总线控制器发送请求
					- 启动计数并广播: 控制器接受到BR信号后,启动内部计数器,并向当前计数值通过设备地址线广播给所有设备
					- 地址比对与截货: 每个设备接口将地址线上的计数值与自身的硬件设备号进行比对.若计数值与自身设备号一致且该设备正处于请求状态,则该设备仲裁成功
					- 总线锁定: 仲裁成功的设备向BS线发送有效信号,总线控制器随机停止计数,设备接管数据线与地址线开始传输
				- **如果做到自定义优先顺序
					- 如果是普通的二进制加法器,查询次序方向是死的,无法做到
					- 查表法: 在总线控制器内部放置一小块容量的RAM或一组可读写的顺序寄存器,输出到地址线上的值不是计数器本身的计数值,而是从寄存器里查询出来的设备号
				- **优势
					- 优先级控制极其灵活
					- 可靠性显著提高: 单个设备接口损坏不会导致其他设备瘫痪
					- 隔离物理位置: 设备的优先级不受物理位置的约束
				- **缺点
					- 硬件开销变大: 需要多加若干条设备地址线
					- 存在电路译码开销: 每个设备接口内部都需要额外的硬件译码器/比较器,用于匹配设备号
					- 查询延迟受限于计数频率: 若被抽中的设备号较大,计数器需要逐个累加到该数值,仲裁延迟随着设备数量增加而变大
			- **独立请求方式
				- ![[Pasted image 20260927092337.png]]
				- $BR_i$(**独立**总线请求线): 专属于设备i,用于单独向控制器申请总线
				- $BG_i$(**独立**总线允许线): 专属于设备i,用于控制器向该设备发送总线使用权
				- BS(**公用**总线忙信号线): 所有设备共享的一根线,用于通知其他设备总线正在被占用
					- BS的约束是仲裁成功者何时能正式使用数据线和地址线
				- **流程
					- 并行申请: 任何需要使用总线的设备,随时通过各自专属$BR_i$线同时向总线仲裁器发送请求
					- 硬件判优: 当BS变低的那一刻,仲裁器内部的排队判优电路在极短的时间内对所有$BR_i$信号进行评估,确定当前优先级最高的设备k
					- 点对点授权: 仲裁器直接拉高对应的$BG_k$线,明确告知设备k获得总线使用权
					- 锁定与传输: 设备k收到属于自己的$BG_k$后,将公用的BS线拉高锁定总线,随后接管地址线和数据线开始数据传输;传输完成释放BS线
				- **优点
					- 响应速度极快: 仲裁过程无需像链式那样逐级传递,也无需像计数器那样逐个递增计数.请求与允许都是点对点并行处理,仲裁开销最小
					- 优先级控制极其灵活
					- 故障隔离与可维护性好
					- 支持设备屏蔽
				- **缺点
					- 控制线数量极多,硬件成本高
					- 芯片引脚开销巨大
		- 分布式

- 总线通信控制
	- **目的**: 解决通信双方**协调配合**问题
	- 总线传输周期
		- 申请分配阶段: 主模块申请,总线仲裁决定
		- 寻址阶段: 主模块向从模块给出地址和命令
			- 主设备向从设备发送地址不仅仅是为了**找到从模块**,更是为了**选中与握手**
				- 解决"多路复用"与"定向选通": 总线上挂载多个从设备,主模块发送地址,只唤醒特定的从设备,其余的从设备依旧保持"睡眠"状态
			- 确定"通信方向": 主模块发送的通信信息通常是"从设备 + R/W(读写位)"
			- 建立传输信道与应答机制
		- 传输阶段: 主模块和从模块交换数据
		- 结束阶段: 主模块撤销有关信息:
			- 清除总线上的电气状态,释放对总线控制权的占用,使总线恢复到"空闲状态"
	- 总线通信的四种方式
		- **同步通信**: 收发双方共享同一根时钟信号线
			- 接受和发送的读写节奏完全由同一时钟沿严格控制
			- 数据输出: 发送方在时钟信号的某个特定边沿将数据电平改变并驱动到总线上
			- 数据输入: 接受方在时钟信号的另一个边沿对其采样,读取电平状态
		    
			- 数据读入
				- T1周期(寻址与发出命令):
					- 主设备在时钟上升沿将目标从设备的地址放到地址线上
					- 主设备同时在控制线上拉低/拉高相应的信号,发出"读命令"
					- 从设备译码器开始解析地址
				- T2周期(从设备相应与准备数据):
					- 对应地址的从设备被激活,识别出这是一次读操作
					- 从设备内部开始访问存储单元或寄存器,准备要返回的数据.在此期间数据线通常仍保持高阻态或稳定状态
				- T3周期(数据传输与采样)
					- 从设备将准备好的数据驱动到数据线上
					- 主设备在T3特定的时钟边沿,对数据上的电平进行采样和锁存,完成数据的接受
				- T4周期(撤销与接受)
					- 读操作完成,进入结束与撤销阶段
			- 在整个读事务完成前,地址信号必须持续有效(即持续在数据线上发送地址);传输结束后,主设备才撤销控制
			
			- 数据输出
				- 在主设备准备写入数据时,数据线和地址线的高低电平早已提前输出并稳定在物理总线上.
				- 在数据和地址电平完全稳定之后,控制线才发出最终的"写使能/写脉冲"指令.
				- 控制信号到达之后,从设备才精准地抓取此时的数据线上已经稳定好的数据,并存入已经确定的地址中
			- 硬件层面三大避错机制:
				- 严格遵循"建立时间"与"保持时间"
					- "建立时间": 要求数据和地址必须在控制信号/时钟边沿到来之前,提前在总线上保持稳定一段时间
					- "保持时间": 要求数据和地址在控制信号/时钟边沿到来之后,还要继续在总线上维持稳定一段时间
				- 控制信号作为"打卡闸机"
				- PCB硬件走线的"等长约束"
		
		- **异步通信**: 通信双方在没有统一时钟信号同步的情况下进行的信号传输与数据交换
			- 不互通(最快但最不可靠)
				- 主方发出请求信号,并维持固定时间后自动撤销
				- 从方检测到请求信号后,发出Ack信号,维持固定时间后自行撤销
			- 双方互不等待,各自按照预设的定时时序撤销信号
			
			- 半互锁
				- 主方发出请求信号,一直保持到接收到从方发送的Ack信号
				- 从方检测到请求信号,发出Ack信号,并维持固定时间后自行撤销
				- 主方接收到Ack信号后,撤销Ack信号
					- 请求信号的撤销是依赖Ack信号;而Ack信号的撤销是自动的
			
			- 全互锁(最慢但最可靠)
				- 主方发出请求信号,一直保持到接收到Ack信号
				- 从方检测到请求信号后发出Ack信号,一直保持到检测到请求信号已撤销
				- 主方接收到Ack信号,撤销请求信号
				- 接收方检测到请求信号消失,撤销Ack信号
			
			- 请求信号是表示主设备**正在发送信号/正在接受信号
			- Ack表示从设备**已经保存完信号/正在发送信号
			
			- 写入数据
				- 寻址与准备数据
					- CPU将目标地址放到地址总线上
					- CPU将要写入的数据放到数据总线上
				- 发送请求
					- CPU在控制总线上发送Req和Write信号,告诉从设备:"地址和数据都准备好了,请接受"
				- 从设备相应与应答
					- 从设备检测到Req,根据AB上的地址选中自己,把DB上的数据锁存进去
					- 完成后,从设备在控制总线上发出Ack
				- 互锁撤销与完成
					- CPU收到Ack信号后,撤销请求信号
					- 从设备检测到请求信号撤销后,跟着撤销Ack信号
					
			- 读出数据
				- 主设备发起请求
					- 主设在地址线上放上目标地址,并在控制线上标为读,发出请求信号
				- 从设备响应与数据传输
					- 从设备译码与准备
					- 数据送上总线
					- 从设备发出Ack
				- 主设备读取数据与互锁撤销
					- 主设备检测到Ack后,采样数据
					- 读完数据后主设备撤销请求信号,从设备检测到无请求信号后撤销Ack
		
		- **半同步通信**
			- 所有动作仍然严格按照系统时钟的上升或下降沿来触发和采样
			- 引入了从设备的应答/等待信号
			- 工作逻辑:
				- 主设备按照标准的同步时钟节拍发出地址和控制指令
				- 主设备在特定的时钟采样点检查从设备的$\overline{WAIT}$信号
				- 若$\overline{WAIT}$有效(表示设备还没好),主设备就在当前时钟周期后自动插入一个或多个和相同的等待时钟周期
				- 一旦从设备准备完毕,拉高/撤销$\overline{WAIT}$,主设备便在下一个时钟沿完成采样和数据写入,总线恢复正常
			
			- 读信号(WAIT是在等从设备把数据找出来并送上总线)
				- T1周期(发送地址): 主设备将目标地址放到地址总线上,并发出控制信号
				- T2周期(检查状态): 慢速从设备译码器发现是找自己,但数据还没从存储介质中取出,于是将$\overline{WAIT}$信号拉低.主设备在T2结束前采样到$\overline{WAIT}$低电平
				- $T_w$周期(插入等待): 主设备保持地址和RD信号不变,在T2和T3之间强制插入一个等待周期$T_w$.在此期间,从设备完成了内部数据的读取,将数据放在数据总线上,并释放了$\overline{WAIT}$
				- T3周期(读取数据): 主设备再次采样发现$\overline{WAIT}$已无效,于是在T3的规定时钟沿将数据总线上的数据存入内部寄存器
				- T4周期(结束释放)
			- 写信号(WAIT是在等从设备把总线上的数据抓取并存入内部)
				- T1周期(发送地址与数据): 主设备将目标地址放到地址总线上,同时要将写入的数据放到数据总线上,并拉高写控制信号
				- T2周期(检查状态): 慢速从设备检测到写请求,但其内部写入电路需要额外时间准备,于是将$\overline{WAIT}$信号拉低.主设备在T2周期采样到该等待信号
				- $T_w$周期(维持数据):主设备保持地址,数据和WR信号在总线上持续稳定驱动,插入等待周期$T_w$.这给从设备流出了充足时间抓取并写入数据
				- T3周期(完成写入): 从设备内部写入完成,释放$\overline{WAIT}$信号.主设备采样到$\overline{WAIT}$恢复正常,准备收尾
				- T4周期(结束释放)
		
		- 分离式通信
			- **核心思想**: 将一次完整的"请求-相应"事务拆分为两个独立的子事务,在等待相应的空闲期释放总线,允许其他设备继续使用
			- **痛点**: 随着CPU频率和总线带宽剧增,慢速设备或高延迟内存的"准备时间"显得极其漫长,导致总线绝大多数时间都在"空转等待",系统的总体吞吐量极低
			
			- **过程**
				- **发起请求
					- 主设备A申请总线,向从设备B发送"读请求"数据包(包含目标地址,数据长度及主设备标识符)
					- 从设备B接受并记录请求信息,向主设备A返回一个已接收的应答信号
					- **立刻释放总线**.在B准备数据的这段时间里,总线完全空闲,其他设备可以进行数据传输
				- **后台处理
					- 从设备B在内部默默进行数据检索和准备,不占用公共总线
				- **返回响应**
					- 数据准备就绪后,从设备B反客为主,充当主设备角色,重新申请总线控制权
					- B获得总线后,将数据联通先前记录的主设备标识符发送回总线
					- 原主设备A根据Tag匹配到这是自己之前要的数据,接受数据并完成整个事务
			- **特点
				- 各模块有权申请占用总线
				- 采用同步方式通信,不等对方回答
				- 各模块准备数据时,不占用总线
				- 总线被占用时,无空闲

## 存储器

- **存储器分类
	- 按照存储介质
		- 半导体存储器 -> 易失
		- 磁表面存储器 -> 不易失
		- 磁芯存储器 -> 不易失
		- 光盘存储器 -> 不易失
	- 按照存取方式
		- **随机访问**: 存取时间与物理地址无关
			- 随机存储器: 在程序执行过程中可读可写
			- 只读存储器: 在程序执行过程中只读
		- **串行访问**: 存取时间与物理地址有关
			- 顺序存取存储器 ->磁带
			- 直接存取存储器 -> 磁盘
	- 按照作用分类
		- 主存储器
			- RAM(随机存储器)
				- 静态RAM
				- 动态RAM
			- ROM(只读存储器)
				- MROM
				- PROM
				- EPROM
				- EEPROM
		- Flash Memory -> 用于主存与辅存之间的缓冲
		- 高速缓冲存储器(Cache) -> 用于CPU与主存之间的缓冲
		- 辅助存储器 -> 磁盘,磁带,光盘

- **存储器的层次结构**
	- 存储器的三个主要特性的关系![[存储器三个主要特性的关系.canvas]]
	- 缓存-主存层次
		- 解决**速度**问题,通常将数据放入高速缓存,弥补CPU与主存之间的速度差距
	- 主存-辅存层次
		- 解决**容量**问题,通常将不常用的数据或程序暂存到外存,扩展可用的存储空间
	
	- 主存储器: 对应实地址,即实际物理存储中的物理单元编号
	- 虚拟存储器(主存储器 + 辅助存储器): 对应虚地址,是程序员或操作系统编制程序时使用的逻辑地址空间.
		- 系统会在程序运行时会将虚地址转换为实地址

### 主存储器

- 主存储器与CPU之间的关系
![[主存储器与CPU的关系|70%]]

- 存储单元地址分配
	- 大端: 数据的高位字节放在低地址
	- 小端: 数据的低位字节放在低地址'
	
	- 如果内存是按字节进行编写的,那么字的首字节的地址即是字的地址

- 主存的技术指标
	- 主存容量: 主存存放二进制代码的总位数
	- 存储速度
		- 存取时间: 存储器的访问时间 -> 读出时间/访问时间 -> 能稳定的读出/写入所花费的时间
		- 存取周期: 连续两次**独立**的存储器操作(读或写)所需的最小时间间隔(比如第一次开始到第二次开始)
	- 储存器的带宽: 位/秒

- 半导体芯片
	- 数据是直接存储在"存储芯片"里的
	- 硬件的本质是将"存储芯片"集成在一块电路板上
	
	- 片选线
		- 片选线属于**控制总线**的一部分(因为起到了控制选择作用),通常是由CPU/主存控制器或外部地址译码器直接连接到存储芯片的CS/CE引脚上
		
		- $\overline{CS}$: 侧重强调"在众多芯片中选择这块芯片"
		- $\overline{CE}$: 侧重强调"开启/激活这块芯片"
		
		- CPU地址总线(高位) -> 片选译码器 -(CS片选信号线)-> 选中芯片
		- CPU地址总线(低位) -> 芯片内译码器 -> CE门控与驱动器 -(字线)-> 激活存储阵列(存储体)
	
	- 读/写控制线
		- 单线控制
			- $\overline{WE}$ -> 低电平写,高电平读
		- 双线控制
			- $\overline{OE}$ -> 允许读
			- $\overline{WE}$ -> 允许写
	
	- 半导体存储芯片的译码驱动方式
		- 线选法
			- 		![[Pasted image 20260929103909.png]]
			- 低位地址经过内部译码后,直接拉高某一条字线
			- 对容量较大的存储芯片不合适,花费的字线数太多
		
		- 重合法
			- ![[Pasted image 20260929105249.png|449]]
			- 低位地址被拆成行地址和列地址,分别经过行译码器和列译码器处理,只有交叉点上的存储单元被选中

- **随机存取存储器(RAM)
	- **静态RAM(SRAM) -> 缓存 -> CPU Cache
		- 利用**双稳态触发器**来存储信息,**只要不断电**,存储的数据就能长期保持稳定
		- 使用重合法，内部具有行译码器和列译码器,将存储地址转化为二维矩阵
	- **动态RAM(DRAM) -> 主存
		- 利用电容进行区分0和1
		- 动态RAM刷新 -> 与行地址有关
			- **问题**: DRAM的电容及其微小,且存在物理漏电现象.如果不进行干预,充了电的电容会在几十毫秒内将电荷漏光,导致数据1变为0
			- **解法 -> 刷新**: 在电容里的电荷漏掉之前,定期对所有存储单元重新充电
			- **刷新模型:
				- **集中刷新
					- 一个周期分为读/写或维持阶段和刷新阶段,在周期末尾,停止所有正常读写操作,连续对DRAM的所有行逐行刷新完,然后再恢复正常读写
					- **存在死区**: 在刷新阶段无法进行读写操作
				- **分散刷新
					- 将刷新均匀分布在正常的工作周期中.将一个逻辑周期分为读写时间和刷新时间,每完成一次正常读写就顺带刷新一行
					- **不存在死区**: 没有长死区,但增加了每次读写的时间开销(读写一次数据,因为硬件总线强行插入了后半段的刷新时间,CPU必须等待刷新时间结束)
				- **异步刷新
					- 利用内存控制器内部的定时器,每隔固定时间插缝向DRAM发送一条刷新指令,每次刷新一行或几行
					- 将刷新时间均匀分散到日常运行中,对系统性能的影响降到最低
						- 刷新命令是不需要立刻执行,内存控制器内部有一个刷新计数器/队列,等到总线空闲的时候才会进行刷新

- 只读存储器(ROM)
	- 掩膜ROM(MROM) -> 厂家将信息直接写在ROM中,用户不可更改
		- 行列选择线交叉处有MOS管为"1"
		- 行列选择线交叉处无MOS管为"0"
	- PROM(一次性-可编程只读存储器)
		- 每个节点上有熔丝
			- 熔丝断为"0"
			- 熔丝未断为"1"
	- EPROM(可擦除-可编程-只读存储器)
		- 每个节点上有N型沟道浮动栅MOS电路
			- D端加正电压 -> 形成浮动栅 -> S与D不导通 -> 0
			- D端不加正电压 -> 未形成浮动栅 -> S与D导通 -> 1
		- 使用紫外线全部擦洗
	- EEPROM(电可擦除-可编程-只读存储器)
		- 既可以局部擦写,也可以全部擦写
	- Flash Memory(闪速型存储器)
		- 比EEPROM快,具备RAM功能

### 存储器的校验

- **背景**: 存储器在受外界干扰(如电磁辐射,噪声等)时,内部存储的0和1电平可能会发生反转
- **解决思想**: 通过增加额外的辅助位数(校验位),使存储器具备发现错误(检测)甚至自动纠正错误的能力
- 编码的检测能力和纠错能力与**任意两组合法代码**之间二进制位的**最少差异数**有关
	- 例如{00000,11111}中任意两组合法代码之间最少差异数就是5
	- L - 1 = D + C(D≥C)
		- L -> 编码的最小距离
		- D -> 检测错误的位数
		- C -> 纠正错误的位数
- **汉明码**是具有一位纠错能力的编码
	- 采用奇偶检验 -> 利用多组交叉重叠的奇偶校验,让校验结果的二进制数值直接等于出错位的编号
	- 采用分组校验
	
	- **公式与规则
		- 校验位个数不等式
			- 若数据位为k,校验位为r,总码长n = k + r,必须满足:$$2^r ≥ k + r + 1$$
				- $2^r$表示r个校验位所能覆盖值的范围
				- $2^r$种状态要覆盖1种无错状态和n种某一位出错的状态
		- 校验位($P_i$)的安放位置
			- 校验位必须放置在二进制编号中只有一位为1的位置(即$2^{i-1}$位置)
		- 分组交叉管辖规则(按位号二进制分解)
			- 汉明码的第j个位置由哪些校验位共同管辖,取决于j的二进制表达中哪一位是1
				- P1: 管辖二进制编号最低位是1的所有位置(1,3,5,7,9....)
				- P2: 管辖二进制编号次低位是1的所有位置(2,3,6,7,10,11....)
				- P3: 管辖二进制编号第三位是1的所有位置(4,5,6,7,12,13....)
	
	- **译码与纠错机制**
		- 接收端重新对各个校验组计算奇偶校验,得到指错字(在接收端对各个校验分组**重新进行奇偶校验运算**直接算出来的)$S_r,.....S_2,S_1$
			- S = 0: 表示传输无错,数据完全正确
			- S ≠ 0: 指错字的十进制数值直接等于出错位置的编号
	- **码距与能力边界**
		- 最小码距(最少差异数)d = 3
			- 如果同时错误数**超过**最大纠错个数(1)的话,可能会出现误纠的情况
		- 扩展汉明码: 在末尾增加一位全局奇偶校验位,使码距d提升至4,具备单错自动纠正,双错自动检测的能力
- 汉明编码一般是配偶校验,但如果是奇校验的话,就需要将所有组和定为1
	- 校验的时候如果所有组均为1,那么无错误
	- 如果有组为0,需要将组合数取反,这个二进制码就是出错地址

### 提高访存速度的措施

- **原因**: 存储器容量提升速度快,但是访存提升速度相对于CPU较慢

- **措施**: 
	- 采用高速器件
	- 采用层次结构Cache-主存
	- 调整主存结构
		- **单体多字系统
			- ![[Pasted image 20261007103459.png|492]]
			- 存储器内只有一个存储体,但增加存储字长.
				- CPU发起一次读/写指令,主存按按地址启动一次存取周期$T_m$
				- 读出时,将连续的m个字一次性锁存到主存MDR中,再由数据总线按字分时送给CPU/Cache
			- 优点: 结构简单,只增加数据总线宽度与MDR容量,即可在一个存取周期内提供和曾被的数据传输率
			- 缺点: 指令和数据必须在物理地址上连续,如果发生条件跳转/不连续访存,读出的后续字会被浪费.只适合连续顺序读写场景;写入单个字时逻辑复杂
		- **多体并行存储器 -> 提升存储器容量
			- 将主存划分为m个独立操作的存储体.每个存储体有独立的地址寄存器,数据寄存器和读写控制电路
			- 根据逻辑地址在各个存储体中的编址方式,分为高位交叉和低位交叉
				- **高位交叉存储器 -> 串行读写
					- **编址方式**: 高位地址表示体号,低位地址表示体内偏移
					- **访存特点**: 连续的逻辑地址分布在同一个存储体中,直到该体装满后才使用下一个体;各个体之间几乎是串行独立工作
					- **优点**: 提升了主存容量
					- **缺点**: 对单进程连续访存没有宽带提升
				- **低位交叉存储器 -> 并行读写 -> 加快了读写速度
					- **编址方式**: 低位地址表示体号,高位地址表示体内偏移
					- **访问特点**:
						- 将连续地址分散到不同的存储体中,CPU按照总线传输周期的间隔,连续向不同存储体发送读写启动指令
						- 当存储体0还在经历恢复/存取周期$T_m$时,存储体1和2已经开始工作.数据以流水线方式源源不断地送上总线
		- **高性能存储芯片
			- SDRAM(同步SRAM)
				- 普通的DRAM均为异步,在异步模式下,CPU发起读写后,必须等待存储芯片内部的逻辑电路自然延迟.CPU无法精准预知数据何时稳定,只能预留较长的安全等待时间,导致总线传输效率低,极难提高频率
				- SDRAM为同步,有了统一的时钟节拍,存储器内部可以像CPU流水线一样,把
				  "行寻址,列寻址,数据读出"分阶段重叠执行
					- 只需要给出一个起始地址,存储器可以在后续连续的几个时钟周期内,远远不断地吐出数据
			- RDRAM
				- 主要解决存储器带宽问题
			- 带Cache的DRAM
				- 在DRAM的芯片内集成了一个由SRAM组成的Cache,有利于猝发式读取
