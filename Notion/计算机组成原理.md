# 计算机组成原理

- 指令集: CPU硬件能理解并执行的**所有**指令的集合与标准规范
- 机器操作码: 专门用来指示CPU应该执行什么具体操作的二进制代码段
- 机器指令 = 机器操作码(执行什么操作) + 地址码(对谁进行)

- $[]$表示取该地址或寄存器中的"数据/内容"
- 没有中括号则表示"部件/寄存器本身"或"地址编号"
	- $[M]\xrightarrow{}X$表示将内存地址M中的存储的具体数值当道通用寄存器X中

- 寄存器: CPU内部一小块用来临时存取二进制数据/指令的高速存储单元
	- 特点: 读写速度极快(与CPU同频),容量极小,紧贴逻辑运算单元和控制单元

## 计算机的基本组成

- 软件: 由具有各类特征功能的信息组成
	- 系统软件 -> 为管理整个计算机系统所编制的程序
	- 应用软件 -> 为实现用户应用所编制的各种程序
- 硬件: 计算机的实体
	- 主机
	- 外设

- **冯诺依曼计算机的特点
	- 计算机由五大部件组成
		- 运算器: 负责进行算术运算和逻辑运算
		- 控制器: 负责从存储器中读取指令,对指令进行译码,并向各部件发出控制信号以协调工作
		- 存储器: 存放数据和程序
		- 输入设备: 将信息转换成机器能识别的形式
		- 输出设备: 将结果转换成人熟悉的形式
	- 指令和数据以同等地位位于存储器,可按地址寻访
	- 指令和数据用二进制表示
	- 指令由操作码和地址码组成
	- **存储程序** -> 具有存储结构的机器称为计算机
	- 以**运算器**为核心

### 系统复杂性管理方法

- **层次化与抽象
	- 分层设计: 将负责的计算机系统自底向上划分为不同的抽象层
		- 每一层都对上层隐藏内部实现的物理细节,仅通过明确定义的接口对外提供服务

- **模块化与结构化
	- 将功能紧密相关的逻辑组合在一起,模块之间通过标准的总线或数据通路通信
	- 标准部件标准化,避免重复设计

- **规范化与标准化
	- 使用结构高度规整的硬件阵列来替代零散的组合逻辑
	- 在RISC架构设计中,尽量采用固定长度的指令格式和统一的译码规则,简化译码器电路中的设计复杂性

- **局部性原理与层次化存储
	- **时间局部性与空间局部性**: 意识到程序访问数据和指令具有极强的时间与空间集中性
	- **层次化构建**: 构建"寄存器 -> L1/L2/L3 Cache -> 主存 -> 外存"的存储金字塔
	- **透明性管理**: 通过硬件机制或操作系统自动管理数据的流动,化解速度与容量的矛盾

### 程序转换为指令

- 将人类的思想转换为计算机硬件能够识别并自动执行的二进制指令序列,并将其装入主存开始运行的过程

$$高级语言/数学算式 \xrightarrow{编制与翻译}汇编/机器指令 \xrightarrow{分配与装入} 主存布局 \xrightarrow{启动指令}设置PC\xrightarrow{自动执行}硬件回路运行 $$
- 指令 = 操作码 + 地址码
- 指令和数据都是保存在存储器中的

#### 存储器的基本组成

- 存储体:  由成千上万个存储单元按规则矩阵排列组成的整体
	- 存储单元: 存放一个存储字的所有存储元集合.
		- 存储单元地址: 每个存储元都有一个唯一的编号
	- 存储元: 存储体的最小物理单元
	- 存储字: 若干个存储元组合在一起,作为一个整体进行并行读写一组二进制位
		- 存储位长: 一个存储字包含的位数
- 译码器: 将二进制地址转换为"物理选通信号"
	- 通过地址总线得到MAR输出的二进制地址码.然后让要取的存储单元与数据总线接通
- MAR与MDR:
	- MAR(存储器地址寄存器)
		- 功能
			- 接受与锁存地址: 暂存CPU发出的主存单元物理地址
			- 驱动地址总线: 地址总线将这个地址送到主存的译码器输入端,从而激活对应的选通线
		- 作用
			- 控制物理寻址: MAR的位数能直接决定CPU硬件一次能够直接寻址的最大存储单元个数
			- 时序与电平隔离: CPU内部的运行速度极快,而外部总线和主存相对较慢.MAR能把CPU发出的地址信号锁存住,确保在整个读/写周期内,给主存译码器的地址信号始终稳定
	- MDR(存储器数据寄存器)
		- 功能
			- 数据中转与暂存: 无论是从主存读取数据/指令,还是向主存写入数据,所有二进制码都必须在MDR停靠中转
			- 隔离与双向缓冲:宽约CPU内部数据通路与外部数据总线,起到双向电平匹配与缓冲的作用
	- 读数据:$$主存存储器 \xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}CPU内部(IR或ACC/X/MQ)$$
	- 写数据:$$CPU内部(ACC等)\xrightarrow{}MDR\xrightarrow{}数据总线\xrightarrow{}主存存储器$$
	- 在逻辑功能上,MAR/MDR是主存储器的地址与数据缓冲接口
	- 在物理上,MAR/MDR是集成在CPU内部的寄存器电路

- 按地址进行寻址

#### 运算器的组成与功能

- 具备的寄存器
	- ACC(累加器):是CPU内部运算器的核心部件之一.他是一个高速暂存单元,专门用来临时存放算术逻辑运算的操作数或中间/最终结果
		- 避免了频繁访问主存,大幅提高执行效率
		- 简化指令长度
	- X(操作数寄存器):内存数据缓冲区
	- MQ(乘商寄存器):辅助/扩展寄存器

**加法操作

指令: 加(进行的操作) M(加数的地址)
初态: ACC -> 被加数
步骤:
	$[M]\xrightarrow{}X$
	在ALU中完成: $[ACC]+[X]\xrightarrow{}ACC$

**减法操作

指令: 减 M
初态: ACC -> 被减数
步骤:
     $[M]\xrightarrow{}X$
     在ALU中完成: $[ACC] - [X] \xrightarrow{} ACC$

**乘法操作

指令: 乘 M
初态: ACC 被乘数
步骤:
	$[M]\xrightarrow{}MQ$
	$[ACC]\xrightarrow{}X$
	$0\xrightarrow{}ACC$
	$[x]×[MQ]\xrightarrow{}ACC//MQ$ 
- 定点数乘法运算执行时,乘积的字长通常会扩大为原来的两倍,一个寄存器就不够用了
	- 我们可以让ACC存储高位的数据,MQ存储低位的数据

**除法操作

指令: 除 M
初态:ACC 被除数
步骤:
	$[M]\xrightarrow{}X$
	$[ACC]÷[X]\xrightarrow{}MQ$
- 余数在ACC中

#### 控制器的组成与功能

**功能
- **解释一条指令**: 控制器的译码器将从内存或指令缓存中读取到二进制机器指令进行分析破译,并将其转化为一串用于控制CPU内部各个部件协调工作的微操作控制信号的过程
- **保证指令的按序执行

**基本组成

- PC(程序计数器): 存放了当前预执行指令的地址,具有计数功能 -> 取指令 (PC) + 1 -> PC
- IR(指令寄存器): 存放当前预执行的指令
- CU(控制单元): 控制CPU内部所有开关的通断,数据流向的闸门,以及各个功能部件的操作模式

- 整个过程
	- PC将指令地址送到地址总线,内存根据这个地址把指令读出,通过数据总线送入CPU的IR.同时PC自动递增指向下一条指令
	- 指令放入IR后,CU将IR里的二进制代码翻译成一排排高低电平信号,去驱动DLU计算,驱动总线切换,驱动寄存器读写.

**完成一条指令的过程

- 取数指令:
	- 先取指令:$$PC\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器(负责数据总线与对应的存储单元对接)$$$$内存目标存储单元\xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}IR\xrightarrow{}CU$$
	- 取数:$$IR\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器$$$$存储单元\xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}ACC$$
- 存数指令:
	- 先取指令:$$PC\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器$$$$存储单元\xrightarrow{}数据总线\xrightarrow{}MDR\xrightarrow{}IR\xrightarrow{}CU$$
	- 存数:$$IR\xrightarrow{}MAR\xrightarrow{}地址总线\xrightarrow{}地址译码器$$$$ACC\xrightarrow{}MDR\xrightarrow{}数据总线\xrightarrow{}存储单元$$

### 计算机硬件的主要计数指标

- 机器字长: CPU一次能处理数据的位数,与CPU中的寄存器位数有关
- 运算速度:
	- 主频: CPU内部数字电路的时钟信号频率
		- 通常以GHz为单位.CPU内部的晶体管和触发器在每一个时钟周期的状态翻转,都依赖这个统一的"节拍器"
		- 主频越高不等于指令执行地越快,与CPU架构设计等有关
	- 核数,每个核支持的线程数
		- 指令最终是由CPU的硬件电路来完成的,线程只是操作系统进行调度和分配CPU时间片的基本单元
		- CPU与线程之间的关系:
			- 操作系统把一个线程调度到某个CPU个核心上运行,本质是把该线程的上下文(比如把线程下一条要执行的指令地址装入PC寄存器)加载到物理硬件中
			- 随后,CPU的硬件逻辑电路开始顺次读取PC指向的指令并加以完成
	- CPI: 执行一条指令所需时钟周期数
		- 先执行一段程序,计算里面指令出现的频率,再对各种指令根据频率加权
	- IPC: 一个时间周期内,能执行多少条指令
	- MIPS：每秒能够执行多少百万条指令
		- 存在的弊端:
			- 忽略了不同指令的复杂度
			- 无法跨不同指令集架构(ISA,Intruction Set Architecture)进行比较
				- RISC(精简指令集)架构倾向于用多条简单指令组合完成一个复杂任务
				- CISC(复杂指令集)架构可能只需一条复杂指令就能完成相同的任务
				- 可能导致完成同一个任务的总时间相同,但指令数不等
			- 忽略了程序编译器的优化影响
	- FLOPS: 每秒浮点运算次数
- 存储容量(存放二进制信息的总位数)
	- 主存储量
		- 存储单元个数 × 存储字长
		- 字节数
	- 辅存容量


## 总线(BUS)

- 总线在物理本质上就是多根信号线(以及电源线,地线)组成的公共传输通道,连接各个部件的信息传输通道

**传输种类
- 串行传输: 数据按位顺序,在一条数据通道上像"糖葫芦"一样一位接着一位按时间顺序传递
	- 虽然每次只有一根数据线能跑,但是频率极高,速度极快
- 并行传输: 数据在多条数据线上同时传输
	- 多条数据线上的数据必须齐头并行,一旦有一条数据线上的数据卡住,其他路都得等着
	- 在高频情况下,走线长度相差几微米,数据就会不同步到达,数据就会彻底混乱
	- 多条线挤在一起,高频高压下会使相邻走线上产生严重的感应噪声,信号失真

**总线的分类
- 片内总线: 芯片内部的总线
- 系统总线: 计算机各部件之间的信息传输线
	- 数据总线
		- 双向
		- **传输内容**: 实际的数据,指令,或运算结果
		- 在CPU,内存,外设之间搬运原始数据,其宽度决定了一次能传输的数据量
	- 地址总线
		- 单向
		- **传输内容**: 目标内存单元或外设端口的物理地址
		- 告诉系统"数据要发给谁"或"从哪里读取数据".其宽度决定了CPU能直接寻址的最大内存空间
	- 控制总线: 
- 通信总线: 用于计算机系统之间或计算机系统与其他系统之间的通信
	- 传输方式
		- 串行通信总线
		- 并行通信总线
