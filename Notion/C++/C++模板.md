# C++ 模板

## 模板概述

模板就是建立通用的模具，大大提高复用性。

- 模板不可以直接使用，它只是一个框架。
- 模板的通用并不是万能的，只能用于一些特定的场景。
- 学习模板并不是为了写模板，而是能在 [[C++STL]] 中运用系统提供的模板。
- C++ 另一种编程思想称为泛型编程，主要是利用模板来实现的。
- C++ 提供两种模板机制：**函数模板**和**类模板**。

## 函数模板

作用：建立一个通用函数，其"返回值类型"和"形参类型"可以不具体指定，用一个虚拟的类型来代表。

```cpp
template<class T>
```

- 要写在函数体之外，不用加分号。
- `template`：声明创建模板。
- `typename`：表示其后面的符号是一种数据类型，可以用 `class` 代替。
- `T`：通用的数据类型，名称可以替换，通常为大写。

### 函数模板的两种使用方式

1. **自动类型推导**（不必说明形参的具体类型，编译器通过对传入参数进行推导得出具体的数据类型）`swap(a,b)`
2. **显示指定类型**（具体指定数据类型）`swap<int>(a,b)`

> 建议使用显示指定类型的方式调用函数模板，因为自己可以确定通用类型 T。

### 注意事项

1. 自动类型推导，必须要推导出一致的数据类型 T，才可以使用（尽管函数中可能没有使用 T，但也要将 T 的数据类型进行说明（使用显示指定类型的方法进行说明））。
2. 模板必须要确定出 T 的具体数据类型，并且数据类型要一致，才可以使用。
3. 上面两条所说 T 的数据类型相同，是仅限于一个函数中（不是所有函数模板的数据类型都相同）。
4. 每一次调用 `template<class T>`，仅对一种函数的定义管用（换句话说就是一个函数模板就需要有一个 `template<class T>`，一一对应），但可以有多个模板参数（例如：`template <class T,class B>`）。

### 函数模板和普通函数的区别

1. 普通函数调用可以发生隐式类型转换。
2. 函数模板用显示指定类型，可以发生隐式类型转换。
3. 函数模板用自动类型推导，不可以发生隐式类型转换。

### 函数模板和普通函数的调用规则

1. 如果函数模板和普通函数都可以实现，优先调用普通函数（即使普通函数只是声明，没有内容）。
2. 可以通过空模板参数列表，强制调用函数模板（例如 `myPrint<>(1,3)`）。
3. 函数模板也可以发生重载。
4. 如果函数模板可以产生更好的匹配（例如：如果调用普通函数，就需要进行隐式类型转换，就会优先调用函数模板），优先调用函数模板。

> 建议：如果有函数模板就不要写普通函数，否则容易出现二义性。

### 函数模板的局限性（具体化）

只有当自定义类型无法适配通用模板，或需要定制行为时，才需要为该自定义类型写显示具体化（例如）：

```cpp
template<> bool myCompare(Person &p1, Person &p2)
```

> 注意：具体化模板是要在函数模板之下创建的。

## 类模板

类模板和函数模板的语法相似，在声明模板 `template` 后面加类，此类就称为类模板。类模板可以直接将自定义数据类型直接传入。

### 类模板成员函数的调用时机

1. 普通类中的成员函数一开始就可以创建。
2. 类模板中的成员函数在调用时才创建。

### 类模板对象做函数参数（三种传入方式）

1. **指定传入类型**：直接显示对象的数据类型（例如 `void func(Person<string,int>&p)`）——最常用。
2. **参数模板化**：将对象中的参数变为模板进行传递（例如 `void func(Person<T1,T2>&p)`，在函数模板中，编译器会动态类型推导得出 T1、T2，相对于指定类型传递会更加灵活）。
3. **整个类模板化**：将这个对象类型模板化进行传递（例如 `void func(T &p)`）——最直接了当。

### 类模板与继承

1. 当子类继承的父类是一个类模板时，子类在声明的时候，要指出父类中 T 的类型（例如 `class Person:public Base<int>`）。如果父类已经是个模板了，如果子类利用了父类的模板需要指出具体的数据类型，否则编译器无法运行。
2. 如果想灵活指定出父类中 T 的类型（也就是在创建对象时，指出具体的数据类型），子类需变为类模板：

```cpp
template <class T>
class Person:public Base<T>
```

### 类模板成员函数类外实现

将类模板中的函数拿出来（例如）：

```cpp
template<class T1>
void Person<T1>::PersonShow()
```

### 类模板分文件编写

问题：类模板中成员函数创建时机是在调用阶段（而在编译时候才能看到类模板的函数实现），导致分文件编写时连接不到。

解决方法：

1. 直接在分文件中包含类模板的源文件（不必再包含头文件，在源文件中就能访问到头文件）——不推荐。
2. 将类模板的声明和具体函数实现放到同一个文件中，并更改后缀名为 `.hpp`。`.hpp` 是约定的名称，并不是强制的——更主流。

### 类模板与友元

- **全局函数类内实现**：直接在类内声明友元并写全局函数的具体内容（在类中定义全局函数，例如 `friend void ShowInfo(Person<T1, T2> &p)`，只是将之前的友元声明再添加成具体函数）。
- **全局函数类外实现**：需要提前让编译器知道全局函数的存在。

> 总结：建议全局函数做类内实现，用法简单，而且编译器可以直接识别。

### 类模板和函数模板的区别

1. 类模板没有自动类型推导的使用方式。
2. 类模板在模板参数列表中可以有默认参数（例如 `template<class T,class B = int>`），而函数模板是不允许这样用的。

## 补充：多文件编译与声明

`typeid(数据类型).name()`：返回的是数据类型的字符串。

在主函数所在的文件中添加头文件或源文件，是将其中的内容"复制"到主函数所在文件中。

- 头文件（`.h`/`.hpp`）：只写函数声明、类声明、宏、常量（必须加头文件保护，`#pragma once`）。
- 源文件（`.c`/`.cpp`）：写实现头文件中声明的函数，确保每个函数只有一份定义。

### 多文件编译的流程

1. **预处理阶段**：`main.cpp` 里的 `#include "Person.cpp"` 被替换成 `Person.cpp` 里的全部代码（声明+实现），相当于 `main.cpp` 里有了模板的完整定义。
2. **编译 main.cpp**：编译器在同一个文件里，既看到 `Person::show()` 的调用，又看到 `Person::show` 的实现代码，直接生成 `Person::show()` 的机器码，存入 `main.o`。
3. **连接阶段**：`main.o` 里已经有了 `Person::show()` 的代码，不需要再找其他目标文件，自然不会报错。

### 是否需要提前声明

需要提前声明：

1. 普通函数"使用在前，定义在后"。
2. 函数/类的循环依赖（例：函数 A 依赖函数 B，函数 B 同时又依赖函数 A）。
3. 跨文件使用且未包含头文件。
4. 模板仅声明，仅指针/引用可用，不能创建实例化对象。

不需要提前声明：

1. 同一个类内的成员函数互相调用。
2. 使用前已完整定义（同一文件中）。
3. 包含完成声明的头文件。

> 注意：如果只在开头声明类名，是不会声明类中的成员；如果要用类的成员，就需要额外声明类的成员。
