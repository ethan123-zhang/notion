## 1. YOLO 与 Transformer

**YOLO** 专注于实时目标检测，核心逻辑是「快」，直接在一阶段内预测出图像中物体的类别和位置。
- 优势：速度极快；对边缘设备友好；不挑数据（小数据集也能快速收敛）。
- 劣势：缺乏宏观全局的上下文推理能力；面对密集重叠、复杂长距离关联场景表现逊色。

**Transformer** 擅长捕捉图像中任意两个区域之间的全局长距离依赖关系，常用于高端图像分类、复杂目标检测/分割及多模态大模型。
- 优势：全局感知能力强，大场景、被遮挡物体的识别上线极高；泛化能力强，数据量越大性能越恐怖。
- 劣势：计算量大且昂贵；缺乏归纳偏置，直接在小数据集上训练极易过拟合；边缘端落地难，部分算子对低功耗硬件不友好。

**YOLO + Transformer**：用于多目标跟踪领域——YOLO 负责找出来，Transformer 负责连起来。

## 2. 目标倾斜导致框变大：YOLO OBB

使用 YOLO OBB 模型（旋转目标检测）：
- 普通 YOLO 输出 `[x, y, w, h]`；YOLO OBB 输出 `[x, y, w, h, angle]`，画出来的框是跟着物体一起倾斜的「斜框」，且速度和普通 YOLO 一样快。
- 标注数据时，标注完的数据必须一致（如都是 `[x1,y1,x2,y2,x3,y3,x4,y4]`）；若因视野遮挡无法完整画出框，只能靠「脑补」框出完整物体。

## 3. K230 的架构与算力

K230：要么只跑传统视觉，要么从头到尾只跑 YOLO。
- **大核**主要跑 Linux 系统，负责网络协议栈、文件系统、USB 驱动、安全管理、高层次用户应用；最核心的是驱动内置的 KPU 和负责复杂的计算机视觉算法。
- **小核**主要跑 RT-Smart（实时多任务操作系统），负责视频输入、显示输出、音频处理。
- 双核都是单核单线程核心，整个 SoC 物理上总共 2 个硬件线程（每核各一个）。小核通过宏内核的分时复用支持成百上千个软件线程；大核作为实时系统同样支持多任务/多线程。

### 分辨率参数三处
```python
sensor = Sensor(width=1280, height=960)   # 传感器硬件初始化（输入源分辨率）
sensor.set_framesize(width=640, height=480) # 帧缓冲区/软件输出分辨率（处理层）
Display.init(Display.ST7701, ..., width=640, height=480) # 显示驱动初始化（输出端）
```
- 摄像头采集 1280×960 大图，通过 API 自动下采样（缩放）或裁剪转成 640×480。

### 如何压榨 K230 算力
1. **将 AI 推理彻底放手给 KPU**；但若模型含 KPU 不支持的算子，会 fallback 回 CPU 计算，大核瞬间卡死。
2. **善用大核的 RVV 1.0 向量加速**：大核自带 128 位向量指令集（RVV）。自定义图像预处理（色域转换、数值归一化）或后处理（YOLO 的 NMS、坐标框映射）不要用纯 C++ 循环，应使用 RVV 优化的 OpenCV 库或直接调用 RVV 内联函数。RVV 是 CPU 硬件底层新的计算马达，官方把库重写了一份，直接调用库即可，底层 CPU 计算快几十倍。
3. **大核与小核通过核间通信（IPC）解耦**：解耦是把紧密交织、互相影响的两个模块切开，各自独立、互不干扰。大核只管拼命识别，识别到就把坐标往「公共邮筒」一扔去处理下一帧；小核自己从邮筒读数据，网络卡不卡大核根本不在乎，相机帧率依旧稳定。
   - 大核：专心做多媒体流水线（视频采集 → KPU 推理 → 结果解析 → 绘制显示）。
   - 小核：把推理出的文本/坐标结果通过共享内存/RPC 发过去，负责网络发送或存 SD 卡。绝对不要在大核里做阻塞性网络请求或文件读写。
   - 共享内存：开辟一块大核小核都能直接读写的区域，适合传大数据（整张图片、特征向量）。
   - RPC 通信：A 核调用函数，底层通过硬件中断把参数发给 B 核执行再返回，适合传控制指令、小数据。
   - Syslink：共享内存和 RPC 的结合升级版，能安全、高速地进行双核数据搬运。
4. **硬件联动（零拷贝传递）**：利用 K230 多媒体缓冲区管理（VICAP、VO、KPU 共用内存），让摄像头采集图像通过硬件直接送入 KPU 输入 Buffer，避免频繁 memcpy 图像数据。
5. **Ai2d**：K230 里专门处理图像的硬件 2D 加速引擎，强制把从 Sensor 搬运的图像数据格式设为 NCHW_FMT 和 uint8，保证数据流全路硬件加速。能在不耗费 CPU 资源的情况下，瞬间把 1080P 画面裁剪、缩放并转成模型要的 NCHW_FMT 格式。
6. 简单的代码不使用 Pipeline，是因为数据量小、CPU 能跑得动；数据量庞大就必须单独调用 Pipeline 和 Ai2d，显式命令底层多媒体硬件管线动起来。
7. YOLO 模型输入分辨率普遍 640×640，但在 K230 这种边缘设备上用 320×320。K230 的 KPU 算矩阵极快，但算完的 NMS 和坐标转换是在 CPU 用纯 MicroPython 跑的。320 是兼顾「识别精度」和「实时帧率」的折中点。PyTorch 导出 ONNX（指定 320）→ nncase 编译 kmodel（继承 320）→ Python 脚本配置参数（填入 320）。远距离手势识别、精密工件检测等对分辨率要求极高的场景可用 640，并可通过提高置信度等方式提高帧率，防止硬件卡死。

### 管线隔离：ISP + VICAP 三通道
ISP（图像信号处理器）+ VICAP（视频输入捕获）组成强大自来水厂，把来自摄像头的同一束光在硬件层面瞬间分流成三根独立管道：
- **通道 0**：1080P、YUV 格式，视觉输出（VO），被 Pipeline 默认接管，用于屏幕高清预览（传感器 → 内存缓冲 → 显示屏硬件底层）。
- **通道 1**：320×320、RGB888P，AI 专供（`img_array = pl.get_frame()`）（传感器 → AI2D 缩放排版 → KPU 神经网络）。
- **通道 2**：640×480、灰度/RGB565，传统算法（`img_native = sensor.snapshot(chn=2)`）（传感器 → 传统内存 → CPU 找色块）。

三条管线全由 DMA（直接内存访问）驱动，完全不需要 CPU 指挥。

### 共享 Buffer（VICAP、VO、KPU 共用内存）
- VICAP（摄像头）采集后直接把数据写进 Buffer，内部集成 ISP，负责原始数据处理（黑电平校正、去噪、自动白平衡等），转成 RGB 或 YUV 图像 Buffer。
- KPU 直接读取 Buffer 数据，算完再放回 Buffer。
- VO（视频输出）读 Buffer 刷到屏幕，进行图层叠加，转成 HDMI、MIPI DSI 等信号发给物理显示屏。
- 串口等通讯引脚大核小核都可控制，但同一时间只能由一个核心完全主导，更推荐用小核控制。

### Sensor、Pipeline、OSD
- **Sensor**：最前端的物理硬件芯片，捕捉光线转成数字信号。
- **Pipeline**：数据传输和处理通道，原始数据经去噪、自动曝光、白平衡后由 DMA 高速搬运到内存，分发给屏幕和 KPU。
- **OSD**：专用显示图层。底层是摄像头实时视频流（动态画面），上层是透明 OSD，在 OSD 图层上画框、写字，像贴纸一样覆盖在视频上方。

### 图像渲染机制
1. **基础板：CPU 暴力软渲染**：未开 AI 管线时，`img = sensor.snapshot()` 把整张图片硬搬到 CPU 内存；`img.draw_rectangle()` 是 CPU 一个像素一个像素替换内存颜色值。
2. **YOLO 管线版：VO 硬件层叠显示**：底层（视频层）直接和摄像头「原画」硬件通道绑定，摄像头拍到什么就直接刷屏幕，CPU 根本不碰这层数据；顶层（UI 层）是盖在视频层上面的全透明玻璃纸。

## 4. mAP（平均精度均值）

mAP 是衡量模型检测准不准的终极指标；**mAP 损失** = 模型量化前后在同一验证集上的 mAP 差值。

测 mAP 时，输入图像预处理必须绝对一致，否则测出的 mAP 会暴跌，那不是量化造成的。

mAP 损失评估：
- < 1%~2%：完美。
- 2%~5%：有优化空间。
- > 5% 或直接崩盘到个位数：严重掉点，模型不能用。

校验集质量低的原因：
1. 数量不对，一般需要 100~500 张。太多转换慢、收益递减；太少无法覆盖数据分布。
2. 数据集场景分布不均，需各种场景图片。
3. 未做正确预处理。

计算过程：
1. 自动匹配：将模型预测框和真实标注框进行位置比对。
2. 判断对错：预测框和真实框重合度达标准且类别一致，判定「找对了」。
3. 绘制 P-R 曲线、算 AP：随着预测框越来越多（置信度门槛从最高慢慢降到最低，允许纳入计算的框越来越多），对预测框计算「查准率」和「查全率」的变化，把点连成折线图；折线图形面积即当前类别的 AP。
4. 得到 mAP：将所有类别 AP 加起来平均。

- `mAP@0.5`：IoU >= 0.5 算合格。
- `mAP@0.5:0.95`：在 0.5 到 0.95 之间每隔 0.05 取一个阈值，求这些阈值的平均值。

结果分析：
- 两者都没掉：模型准确度高。
- `mAP@0.5` 没怎么掉、`mAP@0.5:0.95` 明显暴跌：模型仍能准确找到物体，但画框边缘变粗糙。处理：① 优化 PTQ 校验集（增加图片数量、覆盖各种角度和光照）② 适当提高分辨率（如 320→416），INT8 量化像素跳变误差被大幅稀释。
- `mAP@0.5` 暴跌：模型开始大量漏检或瞎画框。处理：① 优化 PTQ 校验集 ② 切换量化算法/敏感层保护（混合精度：把量化算法从默认 MinMax 切到 KL 或 AdaRound；对极敏感层保留 FP16，骨干网络保持 INT8）③ 提高分辨率为 416 ④ QAT（开发成本极高，不到万不得已不用）。

查准率：画出的框里有多少是对的；查全率：所有物体中找到几个。

K230 使用混合精度：
1. 可将敏感区/检测头区域设为 INT16，既保留高精度，又能全程运行在 KPU 硬件加速器——性能与精度达到最佳平衡。
2. 将敏感层/检测头整个切成高精度，减少硬件来回次数。

## 6. 基于检测的跟踪

流程：
1. 画面进来。
2. 目标检测器（如 YOLO）火力全开，把这一帧所有目标全揪出来（拿到所有坐标框和类别）。
3. 跟踪器计算这一帧框和上一帧框之间的运动相似度（卡尔曼滤波预测位置、交并比 IoU）和外观相似度（ReID 网络提取颜色、纹理特征）。

优缺点：精度高、鲁棒性强，但吃算力。
