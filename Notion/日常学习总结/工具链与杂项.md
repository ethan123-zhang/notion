## 1. g++ 与 CMake

- **g++**：C++ 编译器，将 C++ 代码翻译成二进制程序。
- **CMake**：构建系统生成器。不直接编译代码，而是根据 CMakeLists.txt 生成 Makefile 或其他构建文件，再由 make 调用 g++ 完成编译。

### 在 VS Code 中更改代码后的构建
- 修改 `.cpp` 或 `.h` 文件：直接在 build 目录下运行 `make -j4` 即可，不需要删除 build 重新编译。make 会执行增量编译，自动检测哪个文件变动，只需重新编译那个文件再重新链接。
- 修改 `CMakeLists.txt`（增加了新库、修改 C++ 标准或新增源文件）：在 build 目录运行 `cmake ..`，再运行 `make -j4`。cmake 会更新「建筑蓝图」，告知编译器新规则。
- 环境大改没生效、或删除了关键库导致路径乱了、CMakeLists.txt 报错：删除 build，`cmake ..`，`make -j4`。

### VS Code 指令速记
- `mkdir build`：创建 build 文件夹。
- `cmake ..`：是建筑设计师，看 CMakeLists.txt（设计图纸），检查有没有装必要库，生成 Makefile。
- `make -j4`：是施工队，读 Makefile，用编译器将 .cpp 编译成机器能运行的二进制程序。
- `./` + 二进制文件名：运行该文件。

### CMakeLists.txt 的标准结构
1. 版本声明：规定 CMake 的最低版本。
2. 项目信息：给工程起名。
3. 编译设置：规定 C++ 版本。
4. 寻找依赖：找各库的位置。
5. 声明目标：告诉系统用 main.cpp 生成一个叫 programming 的程序。
6. 链接库：将一些库链接到程序。

注意：
- `include_directories` 传的是「图纸」（头文件 .h）的地址，告诉编译器函数长什么样。
- `link_directories` 传的是「成品零件」（库文件 .so），包含真实机器码逻辑（lib 库）。

## 2. Python 与 C++

- **Python** 是解释型语言，需告诉系统用 Python 环境解释运行 `.py` 文件。
- **C++** 是编译型语言，需先用 CMake 和编译器将 `.cpp` 打包编译成独立的「可执行文件」。

### 树莓派开机自动运行（C++）代码流程
1. 找到编译出的可执行文件路径。
2. 新建一份服务说明书（如 `wuziqi.service`），本质是一个纯文本文件。
3. 将配置模板写入该 service 文件。
4. 命令：
   - `sudo systemctl daemon-reload`：刷新配置（每次改文件后都要执行）。
   - `sudo systemctl enable wuziqi.service`：开机自动运行。
   - `sudo systemctl disable wuziqi.service`：取消自启动。
   - `sudo systemctl start wuziqi.service`：启动文件看效果。
   - `systemctl status wuziqi.service`：检查运行状态。
   - `journalctl -u wuziqi.service -f`：查看日志和报错。
   - `sudo systemctl restart wuziqi.service`：重新启动程序。

## 3. enum / typedef

### enum（枚举）
作用：给一堆数字起名字。
```cpp
enum MotorState {
    MOTOR_STOP,      // 编译器自动当成 0
    MOTOR_FORWARD,   // 自动当成 1
    MOTOR_REVERSE    // 自动当成 2
};
enum MotorState current_state = MOTOR_FORWARD;
if (current_state == MOTOR_FORWARD) { ... }
```
总结：enum 用来消灭代码里的数字常量，让代码像英文文章一样好读。在单片机或底层系统中它们依然是 0、1、2，完全不会额外浪费内存。

### typedef
给数据类型起别名。
```cpp
typedef enum {
    RED,
    GREEN,
    BLUE
} ColorType;   // 给枚举整体起了新名字 ColorType
ColorType my_car_color = RED;
```

### `#define` 和 `typedef` 的区别
- `typedef` 是 C 语言关键字，用于创建类型别名；是语句，句尾加分号。
- `#define` 是预处理指令，用于创建宏定义；不是语句，句尾不加分号。

## 5. 继电器

继电器是用弱电控制强电的电子开关。核心功能：电气隔离与功率放大。
工作原理：
1. 单片机引脚输出高电平，给继电器线圈通电。
2. 线圈产生磁性，把内部触点吸合过来。
3. 触点闭合，强电电路导通，大功率设备开始工作。

结果：单片机的敏感电路与外部高压/强电电路物理上完全隔离，保护芯片不被烧毁。

## 6. 循迹模块选择

1. **红外光电/灰度传感器**：
   - 原理：不同颜色表面对红外光的吸收和反射率不同。发射管不断向下发射红外线：照射浅色（白场地）时红外线大量反射，接收管导通输出低电平；照射深色（黑场地）时被吸收，接收管截止输出高电平。
   - 红外光电 vs 灰度传感器：红外光电在模块上有机械电位器，须手动拧设置阈值，赛道折痕或灯光变亮时数字信号会在 0/1 间疯狂抖动，单片机误判导致小车失控；灰度传感器把反射光强弱原封不动交给单片机，软件上可限幅、滑动平均滤波滤掉微小跳动。
   - 让传感器获得光照免疫的方法：① 发射端：单片机产生高频载波信号（如 38kHz 方波），让红外发射管以此频率疯狂闪烁；② 环境光（太阳光、场馆光）持续稳定（或 50Hz 微弱闪烁），属低频或直流信号；③ 接收端：后面接硬件高通滤波器或专用红外解调芯片，在硬件或软件上把所有直流或低频信号过滤掉，只接受频率刚好是 38kHz 的闪烁光。
2. **视觉循迹模块**：视觉循迹是图像处理与几何特征提取的过程。
   - 算法：① 图像预处理：RGB 转灰度，高斯滤波；② 二值化：设阈值将引导线与背景分隔，提出感兴趣区域；③ 形态学操作：用膨胀和腐蚀填补线段空洞、消除场地反光造成的孤立噪点；④ 特征提取与偏差计算：寻找线条轮廓，计算几何矩获取重心坐标。
3. **电磁与磁条导航**。

## 7. PySide6

1. 具备基础按钮、表格、输入框，还内置极强大的高级模块：
   - `QThread`：多线程管理，防止耗时任务卡死界面。
   - `QSerialPort`：原生的串口通信支持，做下位机/单片机交互极度方便。
   - `QtCharts/PyQtGraph`：支持绘制毫秒级响应的实时数据波形与图表。
   - `QGraphicsView`：支持高帧率图像渲染、ROI 框选和 3D 渲染。
2. 支持官方 Qt Designer，鼠标拖拽完成 UI 布局生成 `.ui` 文件，在 Python 代码中用几行代码加载，实现「界面设计」与「后端算法」完全解耦。

- `QApplication`：程序总引擎，负责管理整个程序生命周期。
- `QWidget/QMainWindow`：主窗口，承载所有东西的「底座」和外壳，定义窗口大小、标题栏、最小化/最大化按钮。
- 控件（Button/Label）：界面上的各种零件。Label 是墙上的告示牌，Button 是墙上的灯光开关。
- `Qt Designer`：可视化设计器，拖拽零件生成外观设计图（main.ui），Python 把图纸设计成真正窗口。
- 信号与槽：连接前台按钮和后台代码的桥梁。

## 8. pip 安装库

在终端中安装：
1. **安装本地安装包**（.whl 或 .tar.gz）：`pip install filename.whl`，pip 直接读取本地磁盘文件解压安装。
2. **安装本地源码文件夹**：从 Github 下载源码压缩包解压成文件夹，文件夹里有 `setup.py` 时：进入源码文件夹，运行 `pip install .`（后面的 `.` 表示当前文件夹），pip 根据配置文件把源码打包安装。
3. **从官方默认源下载**：`pip install 库名`。

相关命令：
- `pip -V`：显示 pip 归属哪个版本的 python。
- `where python`：找所有 python 环境地址。
- `python环境地址 -m pip install nncase`：将库安装到指定环境。

注意：nncase 和 nncase-kpu 只能在 python3.10 环境（不能在 3.12）。

## 9. Docker

- **Docker**：用容器化技术给应用程序封装独立运行环境，每个运行环境是一个容器，运行容器的计算机称为宿主机。
- **Docker 与虚拟机的区别**：Docker 容器之间共用一个系统内核；虚拟机包含一个操作系统的完整内核。

## 12.Git使用方法

- 整体工作方式：工作区修改 -> 缓存区打包 -> 本地版本库封箱存档 -> 上传至github
    - 注意：在本地进行封箱存档时，进行的扫描修改操作。

- 让本地文件夹具备”档案管理“能力：
     1. git init -> 建档
         将普通文件夹变成了Git本地仓库
     2. 创建.gitignore -> 定规则
         告诉系统，要将这个文件夹下的哪些文件进行存档处理
     3. git add . -> 打包
         按照.gitignore中的规则，将目标文件打包进一个暂存区
     4. git commit -m "initial commit" -> 封箱归档
         给打包箱贴上胶带，写上备注。这在电脑本地生成了一条无法篡改的历史记录
- 打通本地与云端的专属通道：
     1. git remote add origin 仓库地址 -> 写入地址
         告诉系统云端的位置，并起个小名叫origin
     2. git branch -M main() -> 挂门牌
         将当前本地的档案主线命名为main
     3. git push -u origin main -> 修专线并发送快递
         把本地的方案发送到云端。-u将本地和云端之间铺设一条专线，之后再发送就不必指明地址了
