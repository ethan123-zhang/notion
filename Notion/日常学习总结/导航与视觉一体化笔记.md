# 导航与视觉一体化笔记

## ROS

- ROS是**通信中介与运行时环境
- 通过话题,服务,运动以及参数服务器,把激光雷达,相机,底盘电机,算法节点等模块连接起来,让数据在系统内流转

**ROS如何保证实时性?**
- **底层通信层**: 支持通过共享内存进行零拷贝传输,百兆点云在进程间传输时延迟低于微秒级
- **执行调度层**: 在节点启动阶段预分配所有内存与信息通道,运行时完全禁止动态内存分配,消除了Linux内存页换入换出带来的耗时抖动
- **操作系统层**: 将内核锁机制全部改成可抢占的互斥量,将ROS2核心计算线程设置为硬实时优先级
- **架构隔离层**: 软实时交给Linux上位机,硬实时交给MCU下位机

### TF

- TF是ROS中最核心的基础库之一,专门用于**管理,追踪和计算**多坐标系之间的相对位姿及随时间的变化关系

- 从**感知计算流**的角度 
	- 自底而上计算: 底盘传感器 -> 里程计 -> 全局地图
		- 底盘传感器测出相对运动 -> 算出了机器人相对于原点的局部轨迹
		- 激光雷达/视觉点云匹配出全局真值 -> 匹配完成后,算法直接算出了机器人在地图里的真实位姿
		- 反解误差补偿项 -> 算出map -> odom的相对偏差补偿值

- **优势
	- **统一标准,免去手动推导旋转矩阵
		- TF库底层自动完成整条链的插值与矩阵乘法
	- **时间旅行与时间戳对齐
		- 机器人运行时,传感器数据到达存在通信和计算延迟,TF在缓冲区内维护了一个时序滑动窗口,开发者可以查询在$t_{1}这一瞬间,相机相对于世界坐标系的位姿$
	- **生态解耦与即插即用
		- 向SLAM,导航栈,机械臂规划等开源库,均深度依赖标准的TF命名.只要底层发布了合规的TF树,顶层算法就能无缝衔接
- **缺点
	- **单树约束(无法成环)
		- TF严格要求坐标变换结构必须是有向无环的树状结构,每个子节点只能有且仅有一个父节点.在闭关运动链中无法直接建模,必须hack成断开的虚拟坐标系
	- **带宽与计算开销巨大**
		- 原生TF默认采用高频广播广播机制.多个节点同时以50~100Hz广播全局坐标变换,会导致大量冗余数据在DDS或ROS网络中泛滥,占用大量CPU与总线带宽
	- **时序延迟与死锁异常**
		- 只要某个传感器的时间戳不同步,或者上位机与边缘端NTP没对齐,lookupTransform就会直接超时或抛出异常,导致导航或控制逻辑卡死
	- **单点断裂导致全局崩溃
		- 坐标链条很长时,若中间某个节点挂掉,整个TF树下游的所有传感器均无法定位到全局世界系,整个感知与规划系统瞬间瘫痪

#### TF树
- 用于**管理机器人各个坐标系之间的空间关系**的核心系统
- TF树是一个**有向无环图**,但在拓扑约束上严格要求为单根树
	- **单父节点约束**: 每个子坐标系只能有且仅有一个父坐标系
	- **无环约束**: 系统中决不允许出现闭环变换
	- **单根**: 通常以全局地图坐标系作为整棵树的根节点

$$map \xrightarrow{T_{map->odom}}odom\xrightarrow{T_{odom->base_link}}baselink$$
- map -> 全局地图坐标系
	- 以整张地图原点为基准的全局世界坐标系.
	- 长期没有累计漂移,但位姿在矫正时会发生离散瞬态跳变
- odom -> 里程计坐标系
	- 一个以开机起点为原点的局部固定坐标系.其核心特征是绝对连续,平滑,无跳变,但伴随运行时间会累计漂移
- base_link -> 本体刚性固连坐标系
	- 刚性绑定在机器人的旋转/几何中心,跟随机器人本体同步平移和旋转
	
- map -> odom是静态地图对累计误差的"校准尺"
	- 低频,允许离散瞬态跳变
- odom -> base_link机器人在局部开机世界中的真实运动位姿
	- 高频,连续,平滑,不可突变,但伴随着打滑和积分,存在长期累计漂移
- map -> base_link是机器人在全局世界地图中的绝对空间位姿真值

- **为什么位姿矫正会跳变?矫正到底发生在何处?
	- **累计漂移瞬间归零**: 轮子微小打滑或IMU偏零每米累计少量偏差,当低频的全局定位算法扫描到全局特征时,会将几十秒内累计的数厘米误差在单一帧时刻一次性拉回真值
	- **回环检测与非线性优化**: 机器人大范围巡航闭环时,后端图优化重新调整历史因子图,产生全局轨迹位姿的离散阶跃
	- **粒子滤波多峰收敛**: 在走廊等长距离对称环境中,粒子分布存在多峰,当识别到新门牌特征时,最高权重粒子瞬间转移产生跳变
- **如何将误差吸收
	- 误差全由map -> odom吸收 -> 定位算法在计算出全局真值$T_{map->baselink}$后面，反解出补偿量

### Nav2导航框架

- **运动规划与轨迹控制的执行引擎
	- 将决策层下发的抽象目标点安全,平滑地转化为底盘电机能够执行的速度控制指令
		- **代价地图层
			- Global Costmap: 融合SLAM静态地图与传感器膨胀层,供长距离路径规划
			- Local Costmap: 维护机器人周身滑动窗口内的即时点云/雷达测距数据,供局部毫秒级避障
		- **规划服务器
			- 调用算法,在Global Costmap上寻找一条从当前base_link位姿到目标点无碰撞的最优几何折线
		- **控制服务器
			- 调用局部轨迹优化算法,以高频周期在Local Costmap上计算未来数秒内的动力学可行轨迹
		- **恢复与行为树调度
			- 负责串联"规划-跟踪-失败重试-原地自旋/后退解脱"的自动状态跳转

### 决策层

- **战术规划与任务仲裁的"大脑"
	- **目标生成与动态调度
		- 根据外部任务状态,动态生成全局目标位姿,向Nav2下发
	- **任务打断与动态抢占**
		- 当机器人巡航过程中检测到突发事件,决策层向Nav2发送Cancel指令或直接重写新的Goal Pose,接管机器人行为
	- **系统级容错
		- 当Nav2触发全部Recovery机制后依然报告导航超时或失败,由决策层决定接下来做什么

## SLAM

- 地图构建与全局漂移消除器
	- 栅格地图供给: 将激光雷达或点云数据实时构建并向ROS话题发布微二维占用栅格地图,作为Nav2全局代价地图的静态参考底图
	- 消除累计漂移

## 卡尔曼滤波

- **线性最小方差最优状态估计器**,而非简单的低通或平滑滤波器
- 适用于**线性高斯系统**
	- 高斯: 噪声符合正态分布

- **核心功能
	- **多传感器状态融合
	- **状态观测器/虚拟软测量
	- **在线系统辨识与自适应参数校准
	- **实时时延补偿与前馈预测

- **核心**: 预测与测量都有误差,两者均服从高斯分布;滤波器的目标是通过加权融合,使估计误差的[[转接文件库#协方差|协方差]]矩阵最小化$$状态转移方程:x_{k} = Ax_{k-1} + Bu_{k} + w_{k-1}$$$$观测方程:z_{k} = Hx_{k}+v_{k}$$
	- $x_k$: 系统状态向量
	- $u_k$: 控制输入量
	- $z_k$: 传感器实际观测向量
	- A,B,H: 分别表示状态转移矩阵,控制输入矩阵,观测映射矩阵
	- $w_k$~N(0,Q): 过程激励噪声,协方差矩阵为Q -> 反应动力学模型对现实世界简化的不确定度
	- $v_k$~N(0,R): 测量传感器噪声,协方差矩阵为R -> 反应传感器硬件的随机热噪声/量化误差
