# 导航与视觉一体化笔记

## ROS

- ROS是**通信中介与运行时环境
- **在ROS 2中,节点通过Publisher向Topic发布Message,其他节点通过Subscriber订阅该Topic,从而接收Message
	- **概念** -> 中文 -> 本质 -> 举例
	- **Topic** -> 话题 -> 有名称,有消息类型的**信息通道** -> /scan
	- **Message** -> 消息 -> 真正传输的数据 -> 一帧激光雷达扫描的数据
	- **Publisher** -> 发布者 -> 向Topic发布消息的**接口** -> LIDAR驱动节点创建的发布者
	- **Subscriber** -> 订阅者 -> 从Topic接收消息的**接口** -> SLAM节点创建的订阅者

![[Pasted image 20261101210252.png]]

- LIDAR,IMU,Encoder不会先经过TF再进入SLAM
- TF不是传感器数据处理节点,而是一套**坐标变换发布,缓存和查询机制
- SLAM输出的地图和定位变换,会被Nav2等节点分别使用
- **在ROS 2中,传感器驱动节点通过Publisher向指定Topic发布Message;SLAM,Mav2等节点通过Subscriber订阅相关Topic,由ROS 2底层通信中间件负责消息传输,使多个节点能够分别获得传感器数据
	- 比如LIDAR发布/scan后
		- SLAM可以用来订阅/scan进行建图
		- Nav2可以同时订阅/scan构建障碍物代价地图(**并不是**LIDAR先把数据交给SLAM,再由SLAM转交给Nav2)

**ROS如何保证实时性?**
- **底层通信层**: 支持通过共享内存进行零拷贝传输,百兆点云在进程间传输时延迟低于微秒级
- **执行调度层**: 在节点启动阶段预分配所有内存与信息通道,运行时完全禁止动态内存分配,消除了Linux内存页换入换出带来的耗时抖动
- **操作系统层**: 将内核锁机制全部改成可抢占的互斥量,将ROS2核心计算线程设置为硬实时优先级
- **架构隔离层**: 软实时交给Linux上位机,硬实时交给MCU下位机

**回环检测与建立回环约束

- **回环检测**: 发现眼前的场景之前来过
- **建立回环约束:** 验证是真的来过了,给出两个时刻之间的位置关系
- **全局优化**: 综合这些信息之后,重新调整位置估计

- **终点的新信息，让我们重新估计了之前的中间位置。
- **地图突然调整,可能是系统利用新证据纠正了旧误差;但调整本身不能证明结果正确
- **SLAM中的位置是一份可以被新证据修订的估计.当前的观测,不仅能帮助判断现在在哪里,也能帮助重新理解刚才走过的路
### TF

- TF是ROS中最核心的基础库之一,专门用于**管理,追踪和计算**多坐标系之间的相对位姿及随时间的变化关系

- 从**感知计算流**的角度 
	- 自底而上计算: 底盘传感器 -> 里程计 -> 全局地图
		- 底盘传感器测出相对运动 -> 算出了机器人相对于原点的局部轨迹
		- 激光雷达/视觉点云匹配出全局真值 -> 匹配完成后,算法直接算出了机器人在地图里的真实位姿
		- 反解误差补偿项 -> 算出map -> odom的相对偏差补偿值

- **优势
	- **统一标准,免去手动推导旋转矩阵
		- TF库底层自动完成整条链的插值与矩阵乘法
	- **时间旅行与时间戳对齐
		- 机器人运行时,传感器数据到达存在通信和计算延迟,TF在缓冲区内维护了一个时序滑动窗口,开发者可以查询在$t_{1}这一瞬间,相机相对于世界坐标系的位姿$
	- **生态解耦与即插即用
		- 向SLAM,导航栈,机械臂规划等开源库,均深度依赖标准的TF命名.只要底层发布了合规的TF树,顶层算法就能无缝衔接
- **缺点
	- **单树约束(无法成环)
		- TF严格要求坐标变换结构必须是有向无环的树状结构,每个子节点只能有且仅有一个父节点.在闭关运动链中无法直接建模,必须hack成断开的虚拟坐标系
	- **带宽与计算开销巨大**
		- 原生TF默认采用高频广播广播机制.多个节点同时以50~100Hz广播全局坐标变换,会导致大量冗余数据在DDS或ROS网络中泛滥,占用大量CPU与总线带宽
	- **时序延迟与死锁异常**
		- 只要某个传感器的时间戳不同步,或者上位机与边缘端NTP没对齐,lookupTransform就会直接超时或抛出异常,导致导航或控制逻辑卡死
	- **单点断裂导致全局崩溃
		- 坐标链条很长时,若中间某个节点挂掉,整个TF树下游的所有传感器均无法定位到全局世界系,整个感知与规划系统瞬间瘫痪

#### TF树
- 用于**管理机器人各个坐标系之间的空间关系**的核心系统
- TF树是一个**有向无环图**,但在拓扑约束上严格要求为单根树
	- **单父节点约束**: 每个子坐标系只能有且仅有一个父坐标系
	- **无环约束**: 系统中决不允许出现闭环变换
	- **单根**: 通常以全局地图坐标系作为整棵树的根节点

$$map \xrightarrow{T_{map->odom}}odom\xrightarrow{T_{odom->base_link}}baselink$$
- map -> 全局地图坐标系
	- 以整张地图原点为基准的全局世界坐标系.
	- 长期没有累计漂移,但位姿在矫正时会发生离散瞬态跳变
- odom -> 里程计坐标系
	- 一个以开机起点为原点的局部固定坐标系.其核心特征是绝对连续,平滑,无跳变,但伴随运行时间会累计漂移
- base_link -> 本体刚性固连坐标系
	- 刚性绑定在机器人的旋转/几何中心,跟随机器人本体同步平移和旋转
	
- map -> odom是静态地图对累计误差的"校准尺"
	- 低频,允许离散瞬态跳变
- odom -> base_link机器人在局部开机世界中的真实运动位姿
	- 高频,连续,平滑,不可突变,但伴随着打滑和积分,存在长期累计漂移
- map -> base_link是机器人在全局世界地图中的绝对空间位姿真值

- **为什么位姿矫正会跳变?矫正到底发生在何处?
	- **累计漂移瞬间归零**: 轮子微小打滑或IMU偏零每米累计少量偏差,当低频的全局定位算法扫描到全局特征时,会将几十秒内累计的数厘米误差在单一帧时刻一次性拉回真值
	- **回环检测与非线性优化**: 机器人大范围巡航闭环时,后端图优化重新调整历史因子图,产生全局轨迹位姿的离散阶跃
	- **粒子滤波多峰收敛**: 在走廊等长距离对称环境中,粒子分布存在多峰,当识别到新门牌特征时,最高权重粒子瞬间转移产生跳变
- **如何将误差吸收
	- 误差全由map -> odom吸收 -> 定位算法在计算出全局真值$T_{map->baselink}$后面，反解出补偿量

### Nav2导航框架

- **运动规划与轨迹控制的执行引擎
	- 将决策层下发的抽象目标点安全,平滑地转化为底盘电机能够执行的速度控制指令
		- **代价地图层
			- Global Costmap: 融合SLAM静态地图与传感器膨胀层,供长距离路径规划
			- Local Costmap: 维护机器人周身滑动窗口内的即时点云/雷达测距数据,供局部毫秒级避障
		- **规划服务器
			- 调用算法,在Global Costmap上寻找一条从当前base_link位姿到目标点无碰撞的最优几何折线
		- **控制服务器
			- 调用局部轨迹优化算法,以高频周期在Local Costmap上计算未来数秒内的动力学可行轨迹
		- **恢复与行为树调度
			- 负责串联"规划-跟踪-失败重试-原地自旋/后退解脱"的自动状态跳转

- Nav2中自带可配置的导航框架,能提供路径规划,路径跟踪,动态避障,代驾地图,行为树等功能,也集成了AMCL等定位组件

### 决策层

- **战术规划与任务仲裁的"大脑"
	- **目标生成与动态调度
		- 根据外部任务状态,动态生成全局目标位姿,向Nav2下发
	- **任务打断与动态抢占**
		- 当机器人巡航过程中检测到突发事件,决策层向Nav2发送Cancel指令或直接重写新的Goal Pose,接管机器人行为
	- **系统级容错
		- 当Nav2触发全部Recovery机制后依然报告导航超时或失败,由决策层决定接下来做什么

## SLAM

- **激光雷达**: 测量周围物体的距离,相当于机器人的空间感知器官
	- **雷达的发射方式
		- **扫描式激光雷达
			- 通过机械或光学方式改变光束方向,逐步扫描空间
		- **面阵/Flash激光雷达
			- 照亮一片区域,由二维接收阵列获取不同位置的深度
	- 激光雷达不要求所有发射出去的光都返回,只需要有**足够的一小部分光**进入接收器,就能进行测距,但如果返回**光太弱**,或者**没有足够的有效光信号**到达接收器,就可能无法测距
- **IMU**: 测量加速度,角速度,帮助判断机器人如何运动
- **RGB相机**: 获取图像,提供问题,颜色及视觉特征
- **SLAM**: 利用这些传感器中的一种或多种数据,估计机器人在哪里,并构建环境地图

- 地图构建与全局漂移消除器
	- 栅格地图供给: 将激光雷达或点云数据实时构建并向ROS话题发布微二维占用栅格地图,作为Nav2全局[[转接文件库#代价地图|代价地图]]的静态参考底图
	- 消除累计漂移

### SLAM建图和自主导航

- **意义**: 将一个受物理世界随机干扰的"盲目机械底盘",升级为具备空间记忆与自适应决策能力的"全自主智能体"

- **步骤
	- **建图
		- **过程**: 让机器在完全陌生的环境中,一边推算自己移动了多少,一边把Odin 1看到的障碍物画在纸上,最后回到起点完成闭环
			- Odin 1获得深度数据 -> 转换为局部三维点云 -> IMU/里程计等预测运动状态 -> 点云匹配/视觉观测等修正位姿估计 -> 计算传感器的全局位姿 -> 将局部点云变换到地图坐标系 -> 更新地图表示 -> 继续获取下一帧 -> 周期性进行全局优化
		- **意义
			- **终止无休止的"历程累积漂移"
			- **提供全局可行域(避免陷入局部死胡同)
			- **建立持久化的空间语义与任务基准
				- 地图是上层决策算法向底层底盘下发宏观意图的通用契约
	- **重定位
		- 机器人丢失位置之后,根据地图和现在看到的特征点和点云,确认自己的初始位姿
	- **定位**
		- 机器人正常运动时不断更新位姿
	- **自主导航
		- **过程:
			- **路径规划**: 知道自己在哪后,算法在地图上画出一条安全绿线,并实时躲开临时障碍物
			- **位姿跟踪**: 机器人一边走一边确认自己是不是还在规划路线上
			- **运动控制**: 向底盘电机下发具体速度指令,驱动轮子前进,转向
		- **意义:
			- 解决如何安全,平稳,自适应地到达目标的行动控制问题

- 在进行**重定位和配准**时,主要看以下信息
	- **面特征(墙壁,地面,桌面)
		- 计算当前点到地图平面的距离
	- **线/边缘特征
		- 计算当前点到地图对应空间直线的距离
	- **局部概率密度与椭球体
		- 计算当前当前点云落在地图各个椭球体高概率区域的总体可能性

#### AMCL

- 利用已经存在的地图 + 激光扫描 + 里程计,持续估计机器人在地图中的位姿
- 用于二维点云图重定位
- 最核心的技术: **粒子滤波
- 运行过程
	- **初始化**: 在地图中生成一批粒子,每个粒子代表一个可能的位置和朝向
	- **运动预测**: 机器人移动后,利用里程计预测每个粒子的新位置,同时考虑运动误差
	- **激光匹配**: 将实际雷达扫描与每个粒子所在位置的地图预测比较,匹配程度越高,粒子权重越大
	- **重采样**: 保留和复制高权重区域的粒子,减少低权重粒子,并重复上述过程

#### FAST-LIO2

- **一种高性能的激光雷达与IMU融合定位,建图算法.它既可以让机器人在快速移动,旋转的过程中,实时估计自身的三维位置和姿态,同时建立三维点云图,又可以定位自身位置
- 核心: **迭代扩展卡尔曼滤波(IEKF)
- 重要设计: **直接使用原始点云进行匹配,以及使用ikd-Tree高效维护地图
	- 相对FAST-LIO通过提取几何特征(比如墙面,边缘等),FAST-LIO2**直接利用经过筛选,降采样后的原始激光点**建立几何约束

- LIO(激光惯性里程计) = 3D LIDAR + IMU
- **IEKF
	- **紧耦合**: 将IMU的运动预测和激光点的几何误差约束放进同一个状态估计过程,联合修正机器人状态
	- **迭代EKF**: 相比于EKF在一个测量更新步骤中围绕当前预测状态进行一次线性化,迭代EKF通过多次重新线性化和更新状态估计,改善非线性测量条件下的局部估计结果
- **ikd-Tree(Incremental k-dimensional Tree)
	- **一种能够快速管理三维点云的动态数据结构 -> 用于查询地图和更新地图
	- **通过空间划分加快邻近点查询,同时还支持高效插入,删除点和动态重平衡
	- 核心思想: **不断划分空间**
		- **不一次性处理所有点,而是通过空间划分,把整个空间分成越来越小的区域
	- **KD-Tree如何实现快速最近邻搜索?
		- **跳过大量不可能包含最近邻的区域
		- 例如
			- 根据查询点坐标,先进入KD-Tree中对应的空间区域
			- 在这个区域找到一些候选点
			- 计算候选点与查询点的距离
			- 检查其他子树的空间范围
			- 如果某个子树的空间包围盒距离查询点比候选点最后一个的距离还远,那么这棵子树就可以跳过了
	- ikd-Tree相较于kd-Tree多了什么?
		- **动态插入点: 新点来了,不需要重建整棵树
			- 如果激光雷达重新扫描到一个新点云G
				- kd-tree会选择整理全部点,再构建新的树
				- ikd-Tree的做法
					- 从根节点A开始,根据当前节点的划分轴比较G的坐标,判断G应该进入左子树还是右子树
					- 一直向下找,直到找到空位置
					- 插入G
					- 更新沿途节点的统计信息并检查树是否失衡
		- **动态删除点: 不需要立即把节点从内存中抠出来
			- 如果每次删除点,都要立即修改整棵树的指针关系,操作会比较复杂
			- **延迟删除
				- 在要删除的点上打删除标记,后续查询时,不会把它作为有效候选点返回,等到需要重建相应子树时,在真正清理掉这些无效节点
				- 延迟删除不能无效积累删除节点,所以ikd-Tree会统计无效节点数量,达到一定条件后触发重建
		- Box-wise Delete
			- **按照一个轴对齐长方体批量删除点
		- **插入时同步降采样
			- 激光对同一片区域进行扫描时,可能会有大量重叠的点重复记录.如果全部保存,不仅会占用空间,还会增加最近邻搜索的开销
			- Voxel Grid降采样时将空间划分成一个个小立方体,每个立方体保留一个代表点.**在插入新点的同时,检查该点所在的小立方体,只保留最靠近立方体中心的那个点
		- **自动检测并修复树的不平衡
			- 如果一直向同一个方向插入,树可能会越来越不平衡,最后导致树的形状越来越像链表,查询效率就会降低
			- 如何判断树是否失衡
				- ikd-Tree会持续记录
					- 当前子树的节点数量
					- 左右子树的节点数量
					- 当前子树中已经删除的节点数量
				- 重建判断标准
					- **树的结构是否失衡
						- 如果树的左节点远大于右节点,那么这棵树就是失衡的
					- **无效节点是否过多
			- 子树重建过程
				- 找到失衡的子树
				- 把子树中的有效点取出来
				- 重新按照空间中的中位数划分
				- 建立一棵新子树
				- 用新子树替换原来的旧子树

- FAST-LIO2能建图,不代表它自带完整的回环检测和全局重定位
	- FAST-LIO2的局部地图匹配能抑制一部分误差,但如果运动过程中出现了累积漂移,标准FAST-LIO2不保证能通哟回环检测主动纠正整条历史轨迹

### 自动避障

### 真实环境与点云不一致的原因

- **鬼影点云 -> 由于反射路径等原因,把真实物体的点错误地放到了不该出现的位置
	- **处理方法**: 优先检查异常是否总是出现在玻璃,反光地面,金属附近.之后可以考虑基于点云置信度,合理距离,多帧一致性等信息进行过滤
		- 鬼影不一定是孤立点,也可能是一整片假点云.所以只做离群点滤波,不一定能解决鬼影
- **飞点 -> 点云像飞出去了一样(可以使用算法解决)
	- 正常情况下,传感器扫描一堵平整的墙,点云应该大致排成一个平面,但是偶尔会出现一些点,偏离墙面,落在墙前方或后面或物理边缘
	- **处理方法**: 如果一个点周围没有多少其他点支持它,就怀疑它是错误的
- **点云残影 -> 物体走了,点越留下了
	- 障碍物曾经真实存在于那个位置,但地图没有及时更新
	- **解决方法**: 区分静态地图和局部代价地图
		- 静态地图 -> 记录墙壁,固定障碍物,场地结构
		- 局部代价地图 -> 根据实时感知,帮助机器人避障
- **点云畸变 -> 直墙变弯墙
	- **一帧点云不一定是在同一个瞬间采集完成的**,如果激光雷达在采集数据的时候,机器人转过了一定角度,点的位置就会出现偏差
	- **解决方法**: 运动补偿/去畸变
- **离群点 -> 不合群的点(可以使用算法解决)
	- **大多数点遵循某种空间规律,少数点明显偏离了这种规律
	- **解决方法**: 半径离群点滤波(判断某个点在规定半径内邻居的个数)

## Odin 1

- **原始点云**: 实时检测障碍物 -> 能知道哪里有物体,以及物体的三维形状,但是不知道颜色
- **上色点云**: 在原始点云的基础上,结合RGB相机照片和标定参数,把颜色对应到空间点上
- **SLAM点云**: 综合激光,相机,IMU等信息进行定位和空间处理,输出适合与运动轨迹,环境地图关联的点云 -> 不仅能看到前面的物体,还能把这些观测与机器人走过的位置联系起来

## KF(卡尔曼滤波)

- **线性最小方差最优状态估计器**,而非简单的低通或平滑滤波器
- 适用于**线性高斯系统**
	- 高斯: 噪声符合正态分布

- **核心功能
	- **多传感器状态融合
	- **状态观测器/虚拟软测量
	- **在线系统辨识与自适应参数校准
	- **实时时延补偿与前馈预测

- **核心**: 预测与测量都有误差,两者均服从高斯分布;滤波器的目标是通过加权融合,使估计误差的[[转接文件库#协方差|协方差]]矩阵最小化$$状态转移方程:x_{k} = Ax_{k-1} + Bu_{k} + w_{k-1}$$$$观测方程:z_{k} = Hx_{k}+v_{k}$$
	- $x_k$: 系统状态向量
	- $u_k$: 控制输入量
	- $z_k$: 传感器实际观测向量
	- A,B,H: 分别表示状态转移矩阵,控制输入矩阵,观测映射矩阵
	- $w_k$~N(0,Q): 过程激励噪声,协方差矩阵为Q -> 反应动力学模型对现实世界简化的不确定度
	- $v_k$~N(0,R): 测量传感器噪声,协方差矩阵为R -> 反应传感器硬件的随机热噪声/量化误差

- 整个卡尔曼滤波的核心性能取决于**Q与R的相对大小
	- **过程噪声协方差Q: 系统动态响应的核心"油门"
		- 目标机动性强,加速度变化越不可预测,Q必须设的越大
	- **测量噪声协方差R: 从数据中直接量化(能直接测量,不用盲猜)
		- R代表传感器自身有多抖
		- 标定方法: 设备静止防止,采集传感器100~500个原始数据,直接计算方差
		- **R通常作为基准锚点,一般先测定并固定不变

## EKF(扩展卡尔曼滤波)

- 适用于**非线性**系统
	- **标准线性KF无法直接用于固定的线性状态转移矩阵精准描述这个模型,而EKF可以通过局部线性化处理它
- 目的: **融合多个存在噪声的传感器数据,得到更可靠的状态估计
