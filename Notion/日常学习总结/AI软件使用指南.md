## 1. Claude Code

### 工作模式
1. **默认模式（Manual Mode）**：修改文件前一定询问用户。
2. **自动模式（Accept Edits Mode）**：自动修改文件，但在终端中执行命令时会停下等待许可。
3. **全自动模式（Auto Mode）**：完全解锁模式，不再询问。
4. **规划模式（Plan Mode）**：只讨论，不修改文件。

### 常用命令
- 在框中执行 bash 命令：命令前面加上 `!`。
- `claude -c`：打开 Claude 并恢复上一次的对话。
- `/compact`：将上下文内容压缩，并转到新的页面。
- `/clear`：清除所有上下文内容。
- `/resume`：查看所有对话。
- `/init`：生成 CLAUDE.md。无论是否压缩上下文，Claude Code 都跟某个对话绑定，需用 `/init` 生成配置。
- `/hooks`：给 AI 设定"自动触发器"和"安全防火墙"，允许 AI 执行完特定操作后自动运行自定义的本地脚本或命令。

### 核心概念
- **MCP**：给 AI 插件化地装上双手和眼睛，让 AI 能安全、标准化地连接各种外部数据源和工具。
- **subagent**：独立的 agent，具有独立的上下文和 skill，独立完成某一件事。启动时会开辟全新的对话窗口，所有对话和分析过程都不会回传到主对话页面。

## 2. Skill

- **Skill**：相当于 Claude Code 的"技能包"，本质上是一个 markdown 文件，里面写了一套针对特定任务的提示词和工作流程。
- **Skill vs Plugin**：skill 本质是一种能力模块；plugin 本质上是打包能力模块和其他配置的容器。
- **生存范围**：
  1. **全局常驻型 skill**：覆盖范围是整个对话。
  2. **阶段/任务型 skill**：直到相关任务结束才会停止。

## 3. Superpowers

开发阶段四步：
1. **需求与架构**：明确意图，评估方案利弊（无法输出任何代码）。
2. **拆解与隔离**：创建独立开发环境，将大需求拆为细粒度卡片（没有任务 Plan，绝不下笔）。
3. **驱动编码**：逐个任务卡片写测试、写实现、重构（没看到测试 FAIL，绝不写功能代码，强制执行红绿重构流程，即 TDD 原则）。
4. **排错与交付**：定位根因、修复 Bug、响应 Code Review、提 PR。
