## 1. 线程

- 树莓派 4 核 4 线程。
- 普通电脑 4 核 8 线程到 16 核 32 线程不等。
- K230 搭载 RISC-V 双核处理器，但不主要靠 CPU 线程，而是靠专门处理矩阵运算的硬件单元（KPU）。

操作系统像超级调度员：假如 2000 个软件线程排队，只有 16 个硬件线程，调度员让这 16 个硬件线程飞速在不同软件间来回切换（速度极快，感觉软件同时运行）。

- **物理线程**：实实在在的加工厂流水线。
- **软件线程**：向系统申请的任务单。

线程数越多并不更快，最优解是 **调用的线程数 == 物理核心数**：
- 普通代码分配的线程全指 CPU；普通 CPU 指令无法直接控制 GPU，需写特殊代码。
- 如果调用的线程数 > 物理核心数，CPU 会把大量算力和时间浪费在「打包、清理、解包」上。

线程处理任务的逻辑（以 GPU 计算为例）：
1. CPU 上启动一个线程读入图像，GPU 复制引擎从电脑内存拷到显卡。
2. CPU 向 GPU 发特殊指令，命令 GPU 用线程计算矩阵乘法。
3. GPU 算完结果存回显存。
4. CPU 得知 GPU 算完，把结果从显存拷回内存，处理后续任务。

同一文件里的代码：
- 不用多线程：单兵作战，严格按顺序一行行执行。
- 用多线程：多兵种协同。代码一旦分配就同时开跑，谁先结束、谁先抢到共享变量，全凭耗时和操作系统调度。

### 线程池
一个常驻线程不够用，弄四个常驻线程，谁闲着谁去领任务执行。
- 原理：程序启动时一口气创建 4 个常驻线程。
- 核心目的：避免频繁创建/销毁线程带来的系统开销。
- 工作方式：有代码要执行时不用新线程，而是把代码当任务打包丢进线程池的任务队列。
- 适用：海量、短小、突发的任务。

### 独立线程
让一个线程在工位上死循环做同一件事。
- 适用：常驻后台的长任务、生产者-消费者流水线。

关闭程序时，如果线程正在死锁或等待 sleep，很难安全退出。必须通过**条件变量的广播**，在收到退出命令时瞬间唤醒所有挂起的线程，让他们安全清理内存并退出。

## 2. 程序卡顿的重灾区

1. **内存分配陷阱**：Python 垃圾回收会自动处理内存，但 C++ 边缘部署时内存卡顿是重灾区。
   - 致命的深拷贝：传递图片时使用指针或引用。
   - 循环内动态分配（while 循环反复申请/释放内存，耗时且造成严重内存碎片）→ 程序初始化时一次性申请大块内存（内存池），循环里只复用。
2. **线程调度与死锁**：
   - 锁的争夺（采图线程写、推理线程读共用一张图像可能读写冲突）→ 加互斥锁；但锁太粗暴，采图线程可能因等不到锁挂起等待，导致摄像头丢帧卡顿。
   - 优先级倒置 → 将重要控制线程放在无用线程前面。
3. **IO 与通信瓶颈**：
   - 串口波特率低 → 提高波特率（115200），并把数据打包成紧凑的十六进制二进制流而非字符串。
   - 总线带宽挤占（摄像头和激光雷达同时占 USB 口，可能抢占同一 USB 控制器带宽，导致画面和点云时断时续）。
4. **物理硬件限制**：
   - 降频保护 → 做好散热。

做好部署级的性能审查。

## 3. CPU / GPU / CUDA / KPU

- **CPU（中央处理器）**：数量少，单个核心极其强大，有复杂控制逻辑和巨大缓存。主要职责：计算机整体统筹和控制。
- **GPU（图像处理器）**：核心数量极其庞大、单个核心结构简单，只适合简单算术运算；无复杂控制逻辑，但极其擅长并行运算。主要职责：屏幕像素颜色计算，机器学习和深度学习训练的绝对主力。
- **CUDA**：英伟达推出的并行计算架构和编程模型，把计算任务合理分配给 GPU 的指挥系统。有 CUDA 的话 GPU 调用效率更高。
- **KPU（神经网络处理器）**：专门为加速神经网络（尤其 CNN）设计的专用硬件，架构完全针对 AI 推理时的乘加运算、池化、激活函数深度定制，功耗低，在特定 AI 任务上效率远超普通 CPU。主要职责：边缘计算设备上的 AI 推理（是推理，不是训练）。

树莓派上也有 CPU 和 GPU：CPU 是跑代码的绝对主力，GPU 为图形渲染和视频硬件编码设计，不支持 CUDA。

## 4. 锁（视觉与多线程领域）

- **互斥锁**：一段时间只能有一个线程有这把锁。作用：保护图像缓冲区。
- **自旋锁**：锁被占用时一直问「好了吗」。应用于视觉处理中某些极短时间的数据交换，避免了线程切换的上下文开销、响应极快，但此时 CPU 无法干其他事；对方占锁时间长会疯狂榨干 CPU。

适用条件：
- 保护一张图片、一个文件、一段网络请求（执行时间 > 1ms）→ 用互斥锁。
- 保护几个数字、结构体、控制开关（执行时间 < 1ms）→ 用自旋锁。

生产者-消费者例子（线程 1 快、线程 2 慢、线程 3 快）：
- 线程 1 执行完将数据放队列 1，唤醒线程 2；线程 2 取数据发现没有就挂起等待唤醒，执行完放队列 2 唤醒线程 3；线程 3 被唤醒后执行。队列 1、2 大小为 1/2。
- 这种情况拒绝轮询而使用挂起，有效降低 CPU 无效算力浪费。

适用场景：
1. **工业相机高频采集**：单线程顺序执行可能高延迟，因为摄像头通电后按固定频率从底层驱动内存缓冲区源源不断吐数据。解决方案：线程 A 读图像、上锁、放入只能放一张图的队列、解锁；线程 B 上锁、拿出图片、解锁、推理。
2. **多相机同步与结果汇总**：机器人身上三个摄像头同时发现障碍物并发信号会数据异常，需加互斥锁，同一时间只允许一个相机霸占串口。

> 先上锁后访问实际上是所有线程达成的「君子协议」。

## 5. std::lock_guard / std::unique_lock / 条件变量

- **`std::lock_guard`**：一旦带上，必须等到花括号结束才能解锁；无法配合条件变量（无法被强行唤醒）；只能在声明变量这一行加锁。
- **`std::unique_lock`**：中途随时支持解锁和上锁；完美配合 wait / wait_for；支持延迟上锁（`std::defer_lock`，先声明后上锁）。

```cpp
cv.wait(lock, [this]{ return !q.empty() || !is_running; });
// 传的是已加锁的 std::unique_lock 对象 + lambda 表达式

cv.wait_for(lock, std::chrono::milliseconds(3000),
            [this]{ return !q.empty() || !is_running; });
// 传已加锁的 unique_lock、限时函数、lambda 表达式
```

- 走到 `cv.wait` / `cv.wait_for` 时，程序先主动执行后面的 lambda：成立返回 true，线程不继续睡；不成立返回 false，线程继续睡。
- 被叫醒或虚假唤醒时：线程会再一次执行 lambda，判断是否继续睡。
- 相比 `cv.wait`，`cv.wait_for` 会在 3s 后被强制唤醒。
- 执行到这两个函数时，锁会被自动解除，方便对队列进行更改。

lambda 表达式：格式 `[捕获列表](参数列表){函数体}`。
- `[this]`：lambda 是黑盒默认看不到外界，`this` 表示类的实例对象本身，允许读取类及其外部成员变量。
- `{return !q.empty() || !is_running;}`：只要队列不为空或程序准备退出，就代表条件满足。

- `cv`：条件变量（condition_variable）。
- `cv.notify_one()`：精准唤醒一个线程。
- `cv.notify_all()`：唤醒所有线程。

```cpp
std::atomic<bool> is_running{true};
```
- 若用普通 bool，在多核 CPU 上，一个核心修改变量，其他核心的 CPU 缓存可能没及时同步，可能引发崩溃；用 atomic，主线程改完后其他核心子线程也会同时修改。

```cpp
signal(SIGPIPE, SIG_IGN);
```
- SIGPIPE：树莓派通过 Socket 向电脑发图片时，电脑端拔网线或程序崩了，Linux 会发 SIGPIPE 信号；默认会直接暴力杀死程序。
- SIG_IGN：遇到 SIGPIPE 什么都别做，当什么都没发生。

如果因网络问题程序被强行关闭，虚拟内存会被回收，但网络端口会被强行锁死。
```cpp
signal(SIGINT, signal_handler); // 遇到 Ctrl+C 拦截，调用回调函数 signal_handler
```

## 6. 软件控制硬件的本质

软件通过改变「寄存器」的二进制状态，进而改变电路中的电压，最终利用电流的物理效应去驱动物理世界。

从代码到电压的过程：
1. **应用软件层**：发出指令的「大脑」。
2. **操作系统与驱动程序层**：翻译官与大管家。应用软件无法直接碰硬件，需向操作系统发起系统调用；操作系统指挥对应驱动程序，把高级语言翻译成硬件能听懂的二进制机器码和寄存器操作指令。
3. **芯片/寄存器层**：硬件的「控制开关面板」。CPU 或 MCU 内部有许多寄存器，驱动程序通过向特定内存写 0/1 改变寄存器状态。寄存器本质是具有特定地址的超高速存储单元。
4. **物理电路层**：寄存器的 0/1 对应电路中的低/高电平。引脚电压变化，电流随之流动。

## 7. STM32 / ESP32 烧录之后的过程

- Flash 里的数据会被擦除，全部设为 1；烧录新代码时，芯片只能把需要的地方把 1 改写为 0。
- 寄存器可以随时、直接改写，不需要擦除。

整体过程：
- 烧录时：清除整片或大块区域（全变 1），把编译好的二进制机器码塞进去。
- 刚通电：所有寄存器自动恢复芯片设计好的一套默认初始值（通常是不工作的安全状态）。
- 运行中：CPU 像精准的乐团指挥，只对代码里指定寄存器地址进行读写，通过位操作修改特定几个 bit。

软复位（烧录后自动启动）时，硬件寄存器没有经历真正的「冷启动断电清零」；按 EN（或 RST）硬件按键或直接拔插 USB 线，寄存器才会初始化再改变。

## 8. 看门狗

### 独立看门狗（IWDG）
单片机内部独立的低速时钟。
- 逻辑：计数器递减，程序必须在减到 0 前重新置位（喂狗）；程序死机导致计数器归零，直接向硬件发复位信号重启单片机。
- 适用场景：
  1. 恶劣电磁环境（工业现场、强电干扰严重，即使主晶振被干扰停摆，LSI 依然能工作，确保把系统拉回来）。
  2. 低功耗待机监控：主时钟关闭但 IWDG 仍可运行以唤醒或监控系统（此时功能是监控芯片能否被正常唤醒；主时钟关闭即休眠，CPU 不再执行任何代码）。
  3. 防死机：防止程序因未知 Bug 陷入死循环或硬件锁死。
- 优劣势：优势是极高独立性与绝对可靠性，只要芯片没烧就能正常工作；劣势是只能判断程序是否还活着，无法判断活得是否正常。

### 窗口看门狗（WWDG）
基于系统主时钟分频。
- 必须在指定时间窗口内喂狗：太晚喂触发复位；太早喂立即触发复位。
- 适用场景：高安全高实时系统；防止程序逻辑错乱。
- 优势：能精准捕捉程序逻辑异常和时序错误。
- 劣势：依赖主时钟，主时钟彻底死掉时也失效；开发难度大，需对代码执行时间算得极精准。

## 9. 内核、操作系统与架构

内核是操作系统的心脏或引擎；操作系统是完整「生态环境」，以内核为核心，外裹工具、软件和界面。内核 = 发动机，操作系统 = 整辆车，架构 = 图纸和结构设计。

**1. 内核**：
1. 内存管理：决定哪些数据进内存、哪些移除，确保软件互不踩踏内存。
2. 进程调度：决定哪个软件优先用 CPU，让多个软件看起来同时运行。
3. 设备驱动：传话筒，让操作系统听懂显卡、键盘、鼠标等硬件语言。
4. 系统调用：上层软件读写硬盘或联网时必须向内核申请权限。

**2. 操作系统**：内核 + 用户界面（桌面/任务栏/终端）+ 系统服务与工具（文件管理器、回收站、网络连接管理器）+ 内置软件（记事本、计算器）。

Ubuntu、CentOS、RedHat、Android 的内核均为 Linux；Windows 的内核为 NT。

**3. 架构**：
- 从内核角度：分**宏内核**和**微内核**，区别在于能把多少功能放进最高权限的「内核空间」。
  - 宏内核：所有核心服务（进程调度、内存管理、文件系统、设备驱动）全装进巨大内核空间。特点：速度极快（通信不跨边界）；牵一发动全身（一个核心服务写不好，整个内核甚至 OS 直接蓝屏/死机）。代表：Linux、Windows、macOS。
  - 微内核：内核只保留最基本功能（进程间通信与同步），把文件系统、驱动程序赶到「用户空间」当普通软件运行。特点：极其安全稳定（网络驱动崩溃只断网，内核不死，自动重启驱动）；开销大/速度较慢（模块跨边界频繁「传话」有性能损耗）。
- 从操作系统层次看：硬件层 → 内核层（紧贴硬件，只有内核有资格直接对硬件发号施令）→ 系统调用层（内核对外的窗口）→ 用户空间与应用层（库、运行环境、图形界面、软件）。
- 从硬件「芯片架构」（指令集架构）看：分 CISC（复杂指令集）和 RISC（精简指令集）。
  - CISC：性能强、功耗大、芯片面积大，具备很多复合指令。
  - RISC：省电、高效、芯片设计简单，把任务拆得很散。
  - CISC 能一条指令做到「从内存读数据 → +1 → 写回内存」，RISC 则一个一个做。

内核负责赋予机器生命（驱动硬件），操作系统负责让生命对人类友好、真正可用。

## 10. 总线 / 内存 / 缓存

**计算机和嵌入式芯片内部**：
1. **总线**：只能调度交通网。
   - 总线仲裁：板子上同时有 CPU、NPU、DMA、GPU 都要读写内存（DRAM），总线内部有仲裁逻辑，按优先级给不同硬件模块发「通行证」，避免数据碰撞。
   - 控制与握手：总线不仅传输数据线，还含地址线和控制线。
   - 位宽与突发传输：CPU/NPU 只给一次起始地址，总线就能连续自动把接下来一大串数据一口气发过去，减少地址寻址开销。
2. **SRAM / Cache**：
   - SRAM 是硬件材质；Cache 是用 SRAM 做出来的「存储调度系统」。
   - Cache 位于 CPU/NPU 和外存之间，工作规律：**局部性原理**——时间局部性（刚用过的数据等会大概率还用）、空间局部性（刚读 0x00，等会大概率读 0x04）。
   - CPU/NPU 拿数据优先找 Cache：有就直接拿走（几乎零等待）；没有则停下来，由总线从外面 DRAM 搬到 Cache 再传。
3. **内存 / 外存**：
   - 内存：运行内存，材质 DRAM，速度比外存快得多但断电清零。
   - 外存：存储空间，种类 Flash、eMMC、SD 卡、硬盘，断电不丢。
   - 外存往内存传输数据用 DMA 控制器自动搬运。
4. **SIMD（单指令多数据流）**：CPU 和加速器内部高效的并行计算技术。普通寄存器一次存 1 个数值；支持 SIMD 的硬件拥有很宽的向量寄存器（128/256/512 位）→ 一条指令同时对一组（多个）数据进行相同数学运算，执行 1 次指令花费一个周期，效率提升好几倍。

## 11. DMA 与 Cache 一致性

如果 DMA 直接把摄像头数据写入 DRAM，而 CPU 的 Cache 里残留上一次处理老图片的旧数据，CPU 读取 Cache 会出现问题。避免方式：
1. **Cache Invalidate**：DMA 搬完新数据后、CPU 读取前，强制把 Cache 里对应这一块旧数据全部作废，CPU 就不会读到旧数据。
2. **Cache Flush/Clean**：如果是 CPU 用 C++ 修改了内存里的特征图、准备交给 NPU 用 DMA 拿走，在 DMA 启动前强制把 Cache 里最新改好的数据刷写回 DRAM，确保 NPU 用 DMA 搬走的是最新版本。
