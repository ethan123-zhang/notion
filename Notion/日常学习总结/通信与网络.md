## 1. 树莓派与其他硬件通过串口联动

- **准备阶段**：写好代码，点击编译，编译出二进制文件（这就是要跑的「实体」）。
- **待命阶段**：在 VS Code 终端输入 `./gomoku_detect` 回车，程序开始跑起来，执行 `while(true)` 循环。因为运行速度极快，会不断问系统「是否收到了信号」；没收到就原地踏步，不消耗太多 CPU。
- **触发阶段**：其他硬件通过串口发送消息后，树莓派硬件缓冲区收到字符，程序在循环中发现信号传入，跳进识别逻辑。

> 注意：VS Code 不会自动「醒过来」。如果程序没在运行，树莓派收到信号只会存在缓冲区内，没有任何代码会去理它。必须手动运行程序进入「监听模式」。

## 2. 同步 / 异步

- **同步通信**：有专门的时钟线。
- **异步通信**：没有时钟线，通过提前约好的「暗号节奏」（波特率）。

主从关系：同步通信中，主机负责在时钟线上产生脉冲，从机接受脉冲。

双工模式：
- **全双工**：拥有两个数据线（如 TX、RX），互不干扰，效率最高。
- **半双工**：只有一个数据线，不能同时发送数据。
- **单工**：只能一边向另一边发数据。

## 3. 常见通信协议

### UART
- 需要 RX、TX；设备没有共享时钟，通信前双方约定一个速度 → **波特率**。

### SPI
- 需要时钟线、MOSI、MISO、CS；两个设备共用同一时钟信号。
- 一个设备做主设备控制时钟，其他设备作从设备（主设备并不唯一）。
- 所有设备共享同一根时钟线、MOSI、MISO；主设备有多个 CS 接口。
- 平时从机处于休眠，对 MOSI 上的数据充耳不闻，并把 MISO 断开（高阻态）防止干扰别人；主机想和从机沟通时，把连着主机和从机的 CS 线拉低即可。
- 一般让一个设备做主机。会出现从机的「哑巴危机」（感知到情况无法第一时间汇报给主机）：只需连接主机和从机的 IRQ/INT 引脚，从机可通过拉低电平触发中断，主机必须给从机发「垃圾数据」，从机才能给主机发数据。

### IIC
- 需要 SDA、SCL；两根线最多连接 127 个设备，每台设备拥有唯一地址。
- 从机不能主动给主机发消息，主机要先开口。SDA 线控制权在从机手上，SCL 控制权在主机手上；主机给从机发送一个时钟脉冲，从机收到后通过 SDA 给主机发一个 bit。

### CAN
- 需要 CAN H、CAN L；每个设备同时发送和接受，通过优先级设置解决冲突。
- 单片机两根线接上 CAN 收发器，收发器引出 CAN_HIGH 和 CAN_LOW（差分线）：
  - 单片机输出低电平：CAN_HIGH 为 3.5V、CAN_LOW 为 1.5V，有电压差 → 逻辑 0。
  - 单片机输出高电平：两者均为 2.5V，无电压差 → 逻辑 1。
  - CAN 收发器也能将收发信号转成逻辑信号。
- **CAN 信号的好处**：普通信号某点受干扰导致电平跳变会出错、不能长距离传输；CAN 采用差分信号（双绞线缠绕），两根线同时受干扰、压差保持不变，保证传输信息不受干扰。
- 设备优先级根据识别码大小规定。

## 4. 串口：字符串与 16 进制

- **发送字符串**：经过查 ASCII 码表转换成 16 进制。可读性强，但浪费带宽（本来 1 个字节可搞定，却用了 3 个字节）。
- **发送 16 进制**：极其高效，上下位机通信都发这种裸数据，接收端拿来直接参与运算。

串口不会自动加换行，需要人为加：
- 若是「文本指令通信」，接收端通常靠检测到 `\n` 才认为一句话说完并开始执行（文本指令通信仅发生在人机交互与调试上）。
- 不加换行的弊端：① 指令粘连，导致指令无效；② 缓冲区溢出，导致程序死机。

数据格式与转换方式（数据发送过程）：
- 起始位（1 位，拉低电平，告知要发数据）→ 数据位（8 位，塞进去的一个字节）→ 校验位（无/None）→ 停止位（1 位，拉高电平，表示停止通信）。

上下位机 ASCII/HEX 匹配：上位机发字符串则串口助手勾「ASCII 显示」；发 16 进制则勾 16 进制显示。

工程控制中一般抛弃文本改用二进制数据帧：
- 文本：下位机收到后需遍历字符解析，单片机的算力白白浪费，导致控制延迟、机械臂卡顿。
- 二进制：下位机收到后用指针强转或内存拷贝，速度极快。

工程上串口通信协议结构：① 帧头 → ② 数据长度 → ③ 数据 → ④ 校验和 → ⑤ 帧尾。

### 串口通信代码

**字符串（上位机发送）**：
```cpp
#include <stdio.h>
#include <string.h>
#include <stdint.h>
// 假设你要发送视觉识别到的目标坐标 X 和 Y
void send_string_data(int target_x, int target_y) {
    char tx_buffer[64];

    // 1. 将数据格式化为字符串，务必加上 \n 作为结束标志符
    sprintf(tx_buffer, "X:%d,Y:%d\n", target_x, target_y);

    // 2. 计算字符串实际长度并发送
    uint16_t len = strlen(tx_buffer);
    uart_send_bytes((uint8_t*)tx_buffer, len);
}
```

**字符串（下位机接收，中断回调）**：
```cpp
#include <string.h>
#include <stdint.h>
#include <stdlib.h>
char rx_buffer[64];
uint8_t rx_index = 0;
// 串口接收中断回调函数：每收到 1 个字节执行一次
void on_uart_rx_string_isr(uint8_t byte) {
    // 检查是否收到换行符 \n (0x0A)
    if (byte == '\n') {
        rx_buffer[rx_index] = '\0'; // 数组末尾补字符串结束符
        // 此时完整接收到一帧字符串，例如 "X:320,Y:240"
        int parsed_x, parsed_y;
        // sscanf 解析非常耗时，不建议在高频控制循环中使用
        if (sscanf(rx_buffer, "X:%d,Y:%d", &parsed_x, &parsed_y) == 2) {
            // 解析成功，将坐标交给运动学逆解或 PID 控制器
            // execute_motion_control(parsed_x, parsed_y);
        }
        rx_index = 0; // 清空索引，准备接收下一帧
    }
    // 防止缓冲区溢出（丢弃超长异常数据）
    else if (rx_index < sizeof(rx_buffer) - 1) {
        rx_buffer[rx_index++] = (char)byte;
    }
}
```
上位机发送什么字符串，下位机就接收什么字符串。

**自定义二进制数据帧模型**：
```cpp
#include <stdint.h>
// 关键操作：取消字节对齐优化！
// 防止编译器为了内存对齐而在结构体中间塞入空字节，导致收发错位
#pragma pack(push, 1)
typedef struct {
    uint8_t header1;   // 帧头1：0x55
    uint8_t header2;   // 帧头2：0xAA
    uint8_t length;    // 数据段长度
    uint8_t cmd_id;    // 指令码 (如 0x01 表示视觉坐标)
    float x;           // X坐标 (占用4字节)
    float y;           // Y坐标 (占用4字节)
    uint8_t checksum;  // 校验和 (防止电机干扰导致数据错乱)
} VisionDataFrame;
#pragma pack(pop)

void send_binary_data(float target_x, float target_y) {
    VisionDataFrame frame;
    frame.header1 = 0x55;
    frame.header2 = 0xAA;
    frame.length = 9;      // cmd(1) + x(4) + y(4) = 9字节
    frame.cmd_id = 0x01;
    frame.x = target_x;
    frame.y = target_y;

    // 计算校验和：将校验位前面所有的字节相加，自然溢出取低8位
    uint8_t sum = 0;
    uint8_t* ptr = (uint8_t*)&frame;
    // 减1是因为最后一个字节是 checksum 本身，不参与计算
    for (int i = 0; i < sizeof(VisionDataFrame) - 1; i++) {
        sum += ptr[i];
    }
    frame.checksum = sum;

    // 暴力美学：直接强转指针，将整个结构体当作字节流发送
    uart_send_bytes((uint8_t*)&frame, sizeof(VisionDataFrame));
}
```

**二进制帧（下位机接收，状态机）**：
```cpp
#include <stdint.h>
#include <string.h>
// 定义状态机的各个独立状态
typedef enum {
    STATE_WAIT_HEADER1,
    STATE_WAIT_HEADER2,
    STATE_WAIT_LENGTH,
    STATE_RECEIVING_DATA,
    STATE_WAIT_CHECKSUM
} RxState;
RxState current_state = STATE_WAIT_HEADER1;
uint8_t rx_payload[32];   // 专门存放纯数据的缓冲
uint8_t expected_len = 0; // 当前帧预期要接收的数据长度
uint8_t payload_idx = 0;  // 接收游标
uint8_t calc_sum = 0;     // 单片机实时自己计算的校验和
// 串口中断回调函数：硬件每收到 1 个字节就触发一次
void on_uart_rx_binary_isr(uint8_t byte) {
    switch (current_state) {
        case STATE_WAIT_HEADER1:
            if (byte == 0x55) {
                calc_sum = byte;
                current_state = STATE_WAIT_HEADER2;
            }
            break;

        case STATE_WAIT_HEADER2:
            if (byte == 0xAA) {
                calc_sum += byte;
                current_state = STATE_WAIT_LENGTH;
            } else {
                current_state = STATE_WAIT_HEADER1; // 假帧头，重置状态
            }
            break;

        case STATE_WAIT_LENGTH:
            expected_len = byte;
            calc_sum += byte;
            payload_idx = 0;
            // 长度防越界保护
            if (expected_len > 0 && expected_len <= sizeof(rx_payload)) {
                current_state = STATE_RECEIVING_DATA;
            } else {
                current_state = STATE_WAIT_HEADER1;
            }
            break;

        case STATE_RECEIVING_DATA:
            rx_payload[payload_idx++] = byte;
            calc_sum += byte;
            if (payload_idx == expected_len) {
                current_state = STATE_WAIT_CHECKSUM; // 核心数据收够了，等待校验位
            }
            break;

        case STATE_WAIT_CHECKSUM:
            // 终极对决：单片机自己算的 checksum 和上位机发来的 byte 一致吗？
            if (byte == calc_sum) {
                // 校验完美通过！提取数据
                uint8_t cmd_id = rx_payload[0];
                if (cmd_id == 0x01) {
                    float received_x, received_y;
                    // O(1) 复杂度的解析：直接把 4 个字节 copy 进 float 变量的内存中
                    memcpy(&received_x, &rx_payload[1], 4);
                    memcpy(&received_y, &rx_payload[5], 4);
                    // 数据极其安全可靠，可以立刻驱动机械执行机构
                    // drive_robot_arm(received_x, received_y);
                }
            }
            // 无论校验成功还是失败（数据被干扰），直接推翻重来，准备迎接下一帧
            current_state = STATE_WAIT_HEADER1;
            break;
    }
}
```

## 5. 树莓派串口配置代码

```cpp
int initSerialBlocking(const string &portname)
{
    int fd = open(portname.c_str(), O_RDWR | O_NOCTTY | O_SYNC); // 打开串口设备
    if (fd < 0)
        return -1;
    struct termios tty;
    tcgetattr(fd, &tty);
    cfsetospeed(&tty, B115200);
    cfsetispeed(&tty, B115200);
    tty.c_cflag = (tty.c_cflag & ~CSIZE) | CS8; // 8 个数据位为一个字节
    tty.c_cflag |= (CLOCAL | CREAD);
    tty.c_cflag &= ~(PARENB | PARODD | CSTOPB | CRTSCTS);
    tty.c_lflag = 0;
    tty.c_oflag = 0;
    tty.c_iflag &= ~(IXON | IXOFF | IXANY);
    tty.c_cc[VMIN] = 1;           // 至少要收到一个字节的数据才能返回
    tty.c_cc[VTIME] = 0;          // 阻塞等待时间，0 表示不等待
    tcsetattr(fd, TCSANOW, &tty); // 应用配置
    return fd;
}
```

## 6. 各平台的串口缓冲与数据切断机制

- **STM32**：底层硬件没有大缓冲区，串口移位寄存器每拼凑满 1 个字节就告诉 CPU。中断模式下数据天生被切断，CPU 永远一个字节一个字节处理；若不使用状态机会拖垮实时性，但这种方式本身会导致 CPU 频繁中断。改良：**DMA + 空闲中断**（DMA 搬数据进数组，串口线路上超过一个字节时间无新数据时触发空闲中断，通知 CPU 去数组取）。
- **ESP32**：UART 硬件内部有 128 字节硬件 FIFO。电平信号来了硬件自动转成字节存在 FIFO 中；收到几个字节后触发底层中断，CPU 极短时间把 FIFO 搬到内存大数组。若高优先级任务霸占 CPU 过久，缓冲区满了会丢数据。
- **Linux**：`read()` 函数和底层硬件有缓冲机制。当 STM32 连续发送 `0x53 0x44`，由于系统任务调度或波特率延迟，`read()` 可能被切断，强硬要求同时读两个可能漏掉指令。

## 8. ESP32 的 USB 口和 COM 口

- **COM 口**：专注于基础的数据调试与烧录。背后连接通用串口转 USB 芯片。主要用途：① 固件烧录与下载 ② 打印调试信息 ③ 供电。不需要 ESP32 跑代码，通电即可识别。
- **USB 口**：专注于高级功能模拟（键盘、U盘、摄像头），身份随代码随意切换。直接引出到芯片内部 USB 控制器，无中转芯片。主要用途：① 模拟外部设备（HID）② 大容量存储（MSC 模式模拟 U 盘）③ 高速数据传输与摄像头流传输 ④ USB 主机模式驱动其他 USB 设备。极度依赖内部固件。

## 9. WIFI 传递信息的方式

通过电磁波。辨别 0/1 的方式：
- **ASK 调幅键控**：振幅低是 0，振幅高是 1。
- **FSK 调频键控**：频率高是 1，频率低是 0。
- **PSK 相移键控**：相位正常是 0，相位移动是 1。

提高传输效率的方式：
- **QAM 正交幅度调制**：同时改变相位和振幅，一个周期可传递多 bit。
- **FDM 频分复用**：多个滤波器频率不同，将不同频率的子载波混合，解读时用不同滤波器分离——把车道从单行转并行（载波 = 运载信号的高频电磁波，子载波 = 按频段划分的电磁波）。
- **OFDM 正交频分复用**：相比 FDM，将频段相近的波用傅里叶变换让其互不干扰——相当于构建多层车道。
- **MIMO 多输入多输出**：发射端和接收端都有多根天线作为信号传输。

多径反射问题：电磁波传输时受多路反射可能叠加，接收方收到两段重叠信号无法识别。WIFI 会在每个符号前添加**循环前缀**作为保护间隔（循环前缀长度必须大于多径反射的最大时间差）。

## 10. 通讯模块选型

1. **以太网**（有线）：极致稳定、低延迟、大带宽。
2. **WIFI**（无线）：提供高带宽的无线数据传输。
3. **蓝牙**（无线）：近距离互联和数据交换。
4. **LoRa**（无线）：极远距离（数公里）、极低功耗、小数据量。

选型：以太网首选，WIFI 次选；数据量小、距离近用蓝牙；距离远用 LoRa。

## 11. SSH

SSH 是网络世界中的一条「隐形加密传送管道」：
- **Shell**：命令行界面，包裹在系统内核外面的一层「壳」，负责接收输入的命令并传给系统。
- **Secure**：将传输的数据进行高强度加密。

功能：
1. 用于文件传输。
2. 远程代码开发：电脑的 VS Code 通过 SSH 协议把「触角」伸进树莓派，直接在电脑图形界面修改树莓派代码，甚至直接调用树莓派环境调试，低延迟。

## 12. Socket 通信

Socket 相当于两个国家之间的电话系统：要在两个不同程序（同一台电脑或跨太平洋）之间传输数据，它们必须各自装一部「电话」，这个接线口就是 Socket——应用程序把数据插进去，网络传到另一端。

需要用到：
- **IP 地址**：相当于大楼地址，帮忙找到网络上某台具体电脑。
- **端口号**：相当于大楼里的房间号/分机号。IP 找到电脑，端口号找到具体程序。

主流派系：
- **TCP Socket**：相当于打电话。必须先拨号、对方接听（建立连接）才能说话；信号不好会重传，确保每句话完整、按序。适用于网页浏览、文件传输、邮件。
- **UDP Socket**：相当于寄明信片。不需打招呼，写地址直接扔邮筒；可能丢、可能乱序，但速度极快。适用于在线游戏、视频直播、语音通话。

### 通信方式
1. USB 虚拟网卡接口。
2. WIFI 模块接口。
3. 本地环回接口（lo）：操作系统内部虚拟的「假网卡」（数据自己给自己发），用于同一设备内进程间通信、本地测试。

「谁连谁」和「谁给谁发数据」是两码事：
- 建立连接阶段：必须一方「开门」、另一方「敲门」。发送方必须知道对方的 IP + 端口；接收方必须知道自身端口，不需要知道对方 IP。
- 传输数据阶段：连接建立后双方都可主动发数据。
- 两个阶段的收发方可以不同，最好是 IP 固定的一方当接收方。

### 粘包 / 半包 / 丢包
- **粘包**：发送端两条消息被接收端接成一条。原因：发送太快或接收不及时，两条消息在接收缓冲区分割不开被一次性读取。
- **半包**：发送端一条消息被接成两条。原因：接收缓冲区大小有限，或网络单次传输最大单元受限，一条完整数据被切两半。TCP Socket 不会放弃任何字节。
- **丢包**：发送了但没收到。串口中：波特率太高、线路电磁干扰、接收方缓冲区满未及时取走。TCP Socket：底层有「超时重传」，丢包会自动重发，看不到数据变少，而是感到严重延迟。

### Socket 断联重连与心跳包机制
1. **数据帧封装**：发送图片时必须加「包头」，接收端先读 4 个字节得知长度，再精准截断。
2. **心跳机制**：电脑端每 3 秒向树莓派发送体积极小的特征字符串，树莓派收到后回复；连续 3 次没收到说明网络已死。
3. **断线重连**：Socket 异常则关闭，进入 while 循环每 2 秒重连电脑端，成功后跳出。

### 信号传递模式
1. 点对点直连：树莓派 → 电脑。
2. 引入服务器的中转：树莓派 → 云服务器 → 电脑/手机/其他设备。

云服务器的优势：
1. **突破局域网限制**：两台设备不在同一局域网就无法 Socket 通讯；云服务器有固定、全球唯一的公网 IP，任何设备都能访问。
2. **解决上传困境**：树莓派要分发大量数据时，局域网上传带宽会被挤爆；云服务器有巨大对称公网带宽。
3. **离线状态下的系统韧性**：树莓派断电/断网/死机重启时，云服务器显示设备离线，还能缓存视频。

## 13. IPv4 / IPv6

- **IPv4**：如 `192.168.1.100`。
- **IPv6**：如 `fe80::1ff:fe00:3a60`（用 16 进制表示），能编写的 IP 数非常多。

## 14. 宽带、路由器、基站、服务器

- **宽带**：数据的高速公路，是「传输服务」和「物理介质」的总成，是连接路由器（或基站）与互联网的物理通路，通常由光纤构成。
- **路由器**：家庭/局域网的「交通枢纽」，核心工作是「寻址」和「转发」，连接这个局域网和外部广域网。
- **基站**：移动网络「超级无线路由」，覆盖范围极大、支持成千上万设备并发，具有极其复杂抗干扰调度的「企业级无线路由器 + 光电转换器」。
- **服务器**：数据的「终点站」与算力中心，所有网络请求的最终目的地。是一台常年不关机、拥有极高稳定性和强大算力的计算机，存储网页、视频、数据库并运行后端业务逻辑。
